# 04. プロット構造・章立て・あらすじ・タイトル

物語構造のテンプレ化と「読後感の薄さ」「水増し」「あらすじの淡々さ」を回避するための構成規約。

---

## 0. 設計資料の分け方

複雑な長編では、規約、世界設定、転換点、プロット、場面メモ、本文を分けると参照しやすい。字数・話数だけで六層の管理を義務付けない。短編や台詞一つなら当該場面の情報で足りる。

| 資料 | 記録すること | 読む範囲 |
|---|---|---|
| 規約 | ユーザー指定、作品の文体方針、必要なガイドライン | 当該作業に関係する規則 |
| 世界設定・人物 | 年齢、関係、制度、能力、場所、現在状態 | 登場人物と場面に関係する正典 |
| 転換点 | 採用した構造で重要な変化 | 現在の局面。必要な作品のみ |
| プロット | 主筋・副筋、人物の変化、伏線、読者への約束 | 現在アークと因果のつながる箇所 |
| 場面メモ | 目的、葛藤、日時、確定事実、開示できる情報 | 当該話と連続する場面 |
| 本文 | 読者へ実際に提示する内容 | 執筆・確認の対象範囲 |

`plot.md`、`scene-cards/`、`world-bible/`等は既存プロジェクトの任意の配置例であり、この配布物には含まれない。資料がない場合は必要事項を短く整理する。別形式の正本を重複作成しない。

- 伏線は設置内容、回収条件、未回収の状態を記録する。回収章は確定事項と予定を区別する。
- 主筋・副筋は現在地と次に動く条件を持つ。全てを毎話進める必要はない。
- 人物の内的変化は起点、転機、到達点と、変わらず残る部分を区別する。
- 時刻・移動・経過日数は一つの正本で管理し、場面メモへ必要分だけ引く。
- プロット変更は可能だが、本文や設定との影響を確認する。計画の固定を目的に人物の自然な選択を抑えない。
- 読む範囲を固定の前後三話に制限しない。直前の状態と関係する因果を選び、全編監査は依頼や具体的な不整合がある場合に行う。

## 1. プロット構造の選択

### 1-1. 基本フレーム

| 構造 | 適性 | 用途 |
|---|---|---|
| 三幕構成 | 導入・展開・解決を整理する参考枠。比率は固定しない | 長編・中編など |
| 起承転結 | ログライン・短編向け | あらすじ構築 |
| 序破急 | キャラアーク向け | 主人公の変化を描く |

構造は作品の読者への約束とジャンルに合わせて選ぶ。転換点のメモは任意資料であり、すべての作品へ強制しない。

### 1-2. 転換点（採用時の参考）

作品が選んだ構造の主要転換点を必要に応じて記録する。シーンカードへは「現在の転換点名・達成すべき機能」だけを必要時に転記する。

| 位置 | 例 | 機能 |
|---|---|---|
| 導入 | 現状の提示 | 主人公の出発点を場面で示す |
| きっかけ | 不可逆な変化 | 以前の日常へ戻れなくする |
| 第一の転換 | 新局面へ | 新しい状況・目標に踏み出す |
| 中間点 | 上昇／下降の転換 | 偽の勝利または偽の敗北 |
| 第二の転換 | 解決へ | 糸口を得て最終局面に入る |
| 結末 | 約束への答え | 冒頭と対になる変化を示す |

### 1-3. Web小説特有の調整

- 作品ページと序盤で約束した読み味を、読者が判断できる早さで具体的な場面として示す
- 報酬駆動型では早めに小さな返済を置く。ミステリー、ホラー、文芸、没入型では謎、恐怖、関係、語りの魅力を約束にできる
- 話末は次話を読む理由を残すが、毎回危機や疑問形にせず、達成、余韻、決断、意味の反転も使う

## 2. 章立てと話数

### 2-1. 1話の長さ
- 作品ごとの正本に記録した目安字数を使う。`work/plot.md`等の管理先がある場合はそちらを参照する
- 投稿先、ジャンル、更新頻度、場面の切れ目、読者の端末を考慮して目安と許容幅を決める
- 字数から場面を水増しせず、一話の状態変化と読み終わりの単位が成立する位置で切る
- 目安から外れた話は自動失格にせず、分割・統合した方が読者の理解と期待に効くかを確認する

### 2-2. 完結話数

完結話数は、読者への約束、主要因果、キャラアーク、未回収事項が閉じる位置で決める。丸い数字も端数も品質や生成手段の証拠ではない。字数や話数を不自然に調整すること自体を避ける。

### 2-3. 章末の引き

話末では、その話で変わった状態を読者が受け取り、次に残る圧力が分かるようにする。問い、危機、選択、達成、余韻、関係のずれ、既知情報の意味反転などから、場面の必然に合うものを選ぶ。同じ型が続く場合だけ変化を検討する。

## 3. あらすじ作成

### 3-1. 診断に使う4要素

あらすじの入口が弱いときは、以下のどこが欠けているか確認する。全要素を同じ比重で詰め込まない。
1. **フック**（読者が「読みたい」と思う仕掛け：意外性・対比・謎）
2. **キャラ**（主人公が誰で、どんな立場か）
3. **葛藤**（主人公が何に立ち向かうか・何を失うか）
4. **期待値**（読者がこの物語に何を期待できるか）

### 3-2. 機能不足を起こしやすいテンプレ

| 確認候補 | 機能が足りない場合の問題 |
|---|---|
| 「これは○○が△△する物語」だけで終える | 立場・変化・期待が具体化されにくい |
| 「これは――の物語」 | 同上 |
| 体言止めの羅列 | リズム単調 |
| 出来事をただ列挙 | フック不在 |
| 大仰な前置き＋淡々本編 | 温度差 |

### 3-3. 例

既存の設定が「侯爵令嬢が婚約を破棄され、辺境の王弟のもとで新しい人生を始める」までの場合：

> 婚約を破棄された侯爵令嬢は、辺境に暮らす王弟のもとで新しい人生を始める。

短く整えることはできるが、中心の葛藤はまだ不明である。魅力を強めるために、借金、得意な経理、崩壊寸前の領地などを勝手に追加しない。本文や確定設定から、彼女の欲求とそこで直面する問題を取得してから具体化する。物語の新規設計も依頼されている場合は、追加案を未確定の案として提示する。

### 3-4. あらすじ自己チェック（観点24対応）

あらすじ作成後・新作公開前に、媒体と作品に関係する項目を確認する：

- [ ] 読者が主人公の立場、変化、対立、期待できる読み味を必要な範囲で判断できる
- [ ] 定型文や体言止めの反復が、新しい情報を運ばずリズムだけを作っていない
- [ ] 作品の入口と中心の問題が具体的に伝わり、本文にない事件を約束していない
- [ ] 「壮大なあらすじ＋淡々本編」の温度差が無い（あらすじのテンションを本文1話の冒頭が引き継げている）
- [ ] 作品と投稿先の表記方針に合い、意図しない揺れがない
- [ ] あらすじ末尾が、作品の読み味と次に知りたいことを損なっていない
- [ ] 句読点と文の長さが、意味のまとまりを追いやすくしている
- [ ] 生成支援を使った場合も、回数を目的にせず、**4要素と本文との整合が満たされるまで**必要な箇所を改稿する

### 3-5. あらすじ依頼の入力項目

Grokへ依頼する場合は、固定プロンプトを複製せず、次の情報を渡す。

```
投稿先と表示上限：
想定読者：
主人公の立場と欲求：
最初の不可逆な変化：
中心対立と失うもの：
読者へ約束する体験：
本文序盤で実際に起こる具体的な場面：
避ける誤読・明かさない核心：

本文との期待を一致させ、説明の重複を削る。出力はあらすじ本文のみ。
```

## 4. タイトル作成

### 4-1. タイトルの役割と現況確認

以下は入口で読み味を伝える構造例であり、現在の主流を固定するものではない。投稿先と対象ジャンルの現況を助言する場合は、最新ランキングを時点付きで確認する：
- 「[主人公属性]、[意外性]だが、[結果]だった件」
- 「[失敗・追放]、しかし[逆転]」
- 「[弱者]の[強み]で[勝利]」

### 4-2. 構成要素

タイトル候補では、一覧で伝える必要がある要素を選ぶ：
- 主人公属性（職業・身分・年齢）
- 意外性・転（「実は」「だが」「しかし」）
- 結果・テーマ（「〜することになった」「〜だった件」）
- 感情フック（「〜だが、もう遅い」）

### 4-3. 点検候補

- 抽象だけのタイトルは、検索入口や読み味が伝わらない場合がある。文芸性や既存読者への訴求が機能するなら一律に排除しない
- 派閥揺れ：タイトル内で `——` `――` `—` 混在
- 意図しない空白や字種の揺れ。外国語等の必要な空白は保つ

## 5. テンプレ展開の回避

### 5-1. なろう典型テンプレ（要警戒）

「ワンオペ経理令嬢→評価されず追放→新しい場所で同じ仕事→ヒーローと結婚→裁判で勝つ→元相手没落」骨格。

### 5-2. 独自要素の注入

テンプレを完全否定する必要はない。新規設計で独自性を考える場合は、作品の核から次を検討する。

- 同じ能力でも、権限・資源・人間関係が変わるとどんな選択が必要か。
- 成功によって誰が何を得て、主人公が何を失うか。
- 相手と対立する理由が変化し、協力や決裂の条件が生まれるか。
- 結末が序盤で約束した体験と、人物自身の選択から生じるか。

料理など無関係な特技、過去の失敗、小道具を一つ足すだけで差別化したとみなさない。既存本文の自然化では、設定変更を伴う案を無断で実装しない。

### 5-3. クライマックスの選択肢を増やす

テンプレ化すると「裁判で勝つ」「審判で勝つ」へ収束しやすい。代替：
- 暴露（証拠の物理提示）
- 第三者の証言
- 主人公の自発的撤退（負けを選ぶ）
- 共闘
- 取引・赦し

## 6. 「水増し」の回避

### 6-1. 水増しの典型症状

- 同じ言い回しがしつこく繰り返される
- あらすじに書いた事件が最初の数話で終わり、その後何十話も停滞
- 別キャラ・別視点で全く同じシーンを再描写
- 退場したキャラがしれっと復活
- 必要な場面が重複説明で遅れ、読者への約束が進まない。投稿頻度自体は評価しない

### 6-2. 各章の進捗チェック

停滞が疑われる章では、読者に何を渡しているか確認する。機能は次のように記録できる：
- 情報開示（読者が知らなかった事実が判明）
- 関係変化（キャラ間の関係が変わる）
- 場所移動に伴う制約・期待・環境の変化（移動だけで進展とはしない）
- 決断（主人公が選択する）
- 喪失または獲得（何かを失う／得る）

余韻、回復、日常への愛着、恐怖の持続にも役割がある。外的な状態変化だけを必須にせず、その章の機能が他の箇所と重なり、削除・統合しても効果を失わない場合に見直す。
