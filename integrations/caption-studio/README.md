# Krea Caption Studio

Krea 2向けのキャラ・コンセプト・スタイルLoRA用データセットを、ローカルでキャプション編集し、そのまま学習する日本語GUIです。

## 起動

ファイルマネージャーでは、このフォルダの **`起動.desktop`** をダブルクリックしてください。実行確認が出た場合は「実行」を選びます。

`.sh`の既定アプリがGVimの環境では、`start.sh`をダブルクリックするとエディターで開くことがあります。ターミナルからは次のコマンドで起動できます。

```sh
/bin/sh "/mnt/solidigm-b/Mang-AI/caption-studio/start.sh"
```

ブラウザに `http://127.0.0.1:3210` が開きます。ブラウザが自動で開かない場合は、このURLを直接開いてください。サーバーを動かしているターミナルを閉じると、モデルと学習処理も停止します。

起動に失敗した場合、エラーはターミナルと`.caption-studio/startup.log`に表示・記録されます。

Linux x86_64用です。Node.js・llama.cpp・Python・PyTorch・Musubi Tuner・CUDA計算ライブラリ・Triton用Cコンパイラ・トークナイザーを`runtime/`と`vendor/`に同梱しています。通常起動時のnpm/pip/nix操作やダウンロードは不要です。ブラウザ、POSIXシェル、NVIDIAドライバーはOS側を使います。NixOSの現環境で検証しています。他のOSやGPUでの動作は未検証です。

## キャプション作業

1. 左上の「＋」で画像フォルダを選びます。パス入力も可能です。サブフォルダの読込、PNG/JPEG/WebP/BMPに対応します。
2. 既存の同名`.txt`は自動で読み込みます。途中までキャプション済みのフォルダから継続できます。
3. キャラクター・コンセプト・スタイルを選び、**トリガーワード**を設定します。「トリガーに覚えさせる特徴」と「画像ごとの違いとして書く要素」を分け、方針を保存します。
4. 右上のモデル設定から「モデルを起動」。準備完了になるまで待ちます。モデルは起動時に自動では読み込まれません。
5. 一括生成は、初期状態ではキャプションが空の画像だけが対象です。選択画像のみ、既存も再生成、1枚ずつの生成、途中停止も使えます。
6. 文章を確認・修正し「下書き保存」またはCtrl/Cmd+S。「確認済み」にすると書き出す対象を絞れます。
7. 「.txt保存」または「.txtを書き出す」で、画像と同じ場所の同名テキストに保存します。

生成した文章はまずアプリ内の下書きとして保存されます。生成中の手動編集は上書きしません。タイムアウトや途中で切れた出力、思考だけの出力はエラーとして扱い、元の文章を保持します。画面を閉じても生成ジョブはGUIサーバーが動いている限り継続します。サーバー再起動後は同じフォルダを開くと保存済みの下書きを復元します。

### 一部書き換えとトリガー統一

「一括編集」で、選択画像・全画像・確認済みを対象に次を行えます。

- **文字列の部分置換**：完全一致する文字列をすべて置換。正規表現は使いません。
- **先頭・末尾への追加**：入力した文章をそのまま追加。必要な空白や句読点も入力してください。
- **トリガー統一**：保存済みのトリガーを先頭に配置。旧トリガーを指定すると先頭から除去し、新トリガーを重複させません。

変更前後をプレビューしてから適用します。空のキャプションはスキップ。変更された画像は未確認に戻ります。適用前の文章を`.caption-studio/edit-history/`に残します。

### 保存保護

- .txtを上書きする際、元の内容を`.caption-studio/backups/`に保存します。
- 別のソフトが.txtを変更していた場合は、上書きを止めます。フォルダを再読込し、下書きと外部変更を確認してください。
- 同じフォルダに`image.png`と`image.jpg`があるなど、同名の.txtが衝突する場合は保存を止めます。画像名を変更してください。
- 一括生成は既存キャプションを初期状態でスキップ。再生成前の下書きは`draft-history/`に残します。
- キャプション一覧をJSONLでも保存できます（ガイド内）。

## LoRA学習

1. キャプションとトリガーを確認し、右上の「LoRA学習」を開きます。
2. 全画像・確認済み・選択画像から対象を指定します。
3. 「用途・画像数・空きVRAMから推奨値を設定」で初期値を選びます。
4. 「設定を計算・検査」でキャプション、トリガー、モデルファイル、GPUを検査します。問題がある場合は開始できません。
5. 出力先と実行コマンドを確認し「この設定で学習開始」。画像キャッシュ、テキスト埋め込み、学習の順に進みます。
6. 完了すると画面に`.safetensors`の保存パスが表示されます。

GUIが起動したGemmaは学習開始時に停止します。他のアプリが使うGPUプロセスは停止しません。使用中のVRAMが変わったときは再度推奨値を計算してください。

学習は`training-runs/<日時とID>/`に固定した画像とキャプションのコピーを使います。元画像と元.txtは変更しません。下書きの最新内容も学習に使用できます。画像を変更したときの古い埋め込みの混入を防ぐため、実行ごとに新しいキャッシュを作ります。学習対象には3枚以上の画像と、設定トリガーで始まる非空キャプションが必要です。

設定・トリガーは`plan.json`、`captions.jsonl`、`trigger.txt`に、進捗は`train.log`に残ります。LoRA自体のメタデータにもトリガーを保存します。生成時はこのトリガーをプロンプトに含めてください。これは通常のテキスト文字列であり、トークナイザーに新しい特殊トークンを登録する処理ではありません。

停止時は既に保存済みのチェックポイントが残ります。停止直前のステップの保存や、optimizerを含む途中再開は実装していません。短い試行を行い、途中保存されたLoRAを比較して学習量を調整してください。

### 推奨設定の考え方

基準はrank/alpha 32、全Linear層、SDPA、BF16 mixed precision、gradient checkpointing、解像度に応じた`krea2_shift`です。VRAMが少ない場合はscaled FP8とCPUへのblock swapを提案します。FP8の必要な2フラグは同時に設定します。

学習率はキャラ5e-5、コンセプト8e-5、スタイル1e-4。画像数に応じた提示回数を基に300〜3000ステップを提案します。これらの用途別学習率・ステップ数・VRAM閾値は、本アプリの**初期仮説**であって最適値の保証ではありません。データセットの質、画像数、学習対象、GPUの実際の使用状況によって調整してください。画面には提案理由と手動調整項目を表示します。

## 同梱モデル

`models/`内の次の実ファイルを使用します。既存の別環境からも参照されていたため、元ファイルは削除せずコピーしました。

| 用途 | ファイル |
|---|---|
| キャプション用Gemma | `models/caption/UNSEEN_Gemma_4_26B_NSFW_Q4_K_M.gguf` |
| 画像認識projector | `models/caption/mmproj-gemma4-vision-f16.gguf` |
| LoRA学習のRAW DiT | `models/krea2/krea2_raw_bf16.safetensors` |
| VAE | `models/krea2/qwen_image_vae.safetensors` |
| 学習用テキストエンコーダー | `models/krea2/qwen3_vl_4b.safetensors` |

Gemmaはキャプション生成用です。Krea 2の学習側テキストエンコーダーは別のQwen3-VLです。学習済みLoRAをTurboで利用する場合の画像生成アプリは含みません。

## 調査と初期方針

2026年10月1日に以下の一次資料を確認しました。

- [Krea 2 Technical Report](https://www.krea.ai/blog/krea-2-technical-report)：自然言語による詳しい画像記述、OCRや既知情報の利用。
- [Krea 2 LoRA training](https://www.krea.ai/blog/krea-2-lora-training)：固定したくない背景・小物は記述し、キャラやスタイルのデータセットに適切な変化を持たせる。
- [Krea 2公式リポジトリ](https://github.com/krea-ai/krea-2)：RAWで学習し、Turboで利用する推奨。
- [公式Prompting guide](https://github.com/krea-ai/krea-2/blob/main/docs/prompting.md)：自然言語と画像内文字の表現。これは推論用の資料です。
- [Musubi TunerのKrea 2資料](https://github.com/kohya-ss/musubi-tuner/blob/main/docs/krea2.md)：実装の設定と制約。
- [llama.cpp server](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)：マルチモーダルAPIと推論設定。

キャラでは衣装・表情・背景、スタイルでは被写体・物体色・構図、コンセプトでは対象を囲む物体や関係を記述するよう、用途別のプロンプトを設けています。対象固有の特徴を省略するか文章に含めるかは選択可能です。英語90〜160語の初期値や特徴省略は、公式が保証したLoRA規則ではありません。画像認識の誤りや省略指示からの逸脱はあり得るため、生成後の確認を前提にしています。

## 開発・検証

アプリ本体はNode.js標準ライブラリとHTML/CSS/JavaScriptだけで構成しています。

```sh
./runtime/node --test tests/*.test.mjs
./start.sh --no-browser
```

`examples/demo/`は操作テスト用の花瓶画像3枚です。実データセットではありません。`docs/`に画面と実機検証結果を保存しています。1ステップの動作確認用LoRAは品質検証済みの学習モデルではありません。

依存の出所は`runtime/bundle-manifest.json`、Python各パッケージのライセンスは各dist-info、Musubiのライセンスは`vendor/musubi-tuner/README.md`のLicense節を参照してください。GPUドライバーに含まれる`libcuda`はOS側を使います。
