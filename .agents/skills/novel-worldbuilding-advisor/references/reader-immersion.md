# 読者を世界観で惹き込む開示設計

作った世界を「どう見せるか」の各論。Web小説の読者はスマホで読み、説明が続けば戻るボタンを押す——本格世界観と可読性は対立しない。**対立するのは「作り込み」と「説明したい欲」**である。

## 1. 大原則：説明するな、体験させろ

- **キャラにとっての当たり前を、キャラは解説しない**。世界の情報は、キャラの行動・不便・失敗・習慣の摩擦を通して漏れ出るのが自然な開示。
  - 説明型：「この国では塩が貴重で、税がかけられている」
  - 体験型：塩壺に鍵がかかっている。客に塩を出したら同席者が目を剥く。——読者は「塩が貴重らしい」と**自分で発見**する。
- **読者の発見は説明の10倍記憶に残る**。世界観で惹き込むとは、読者に小さな発見を連続させること。
- 五感で開示する（本リポジトリ三大原則2と同根）：技術レベルは「照明の暗さ・夜の静けさ・道の泥」で、経済は「食卓」で、宗教は「食前の仕草」で見せられる。

## 2. 情報開示のペース配分（Web連載向け）

- **新規固有名詞は理解できる密度で配給する**。人名・地名・組織名・単位を合算し、読者がその場で区別する必要のある数を抑える。固定上限ではなく、文脈、既出知識、場面の速度で判断する。
- **説明の分割払い**：1つの制度・歴史は一度に説明しきらず、①存在の提示（違和感）→②部分の理解（体験）→③全体像（プロットに関わる瞬間）の三分割で出す。読者が「知りたくなってから」次を出す（novel-plot-advisor の「設定は読者が読みたくなってから」と同一原理）。
- **序盤（1〜3話）は世界より約束**：世界観自慢を序盤の掴みにしない。序盤の世界描写は「主人公の困りごとに絡む範囲」に限定し、世界の深さは中盤から効かせる長期資産と考える。
- **説明回を作らない**：歴史講義・システム解説だけの話は離脱点になる。どうしても必要な情報量は、利害の対立する会話（教師と生徒ではなく、交渉・口論・査問）に載せると講義臭が消える。

## 3. ディテールの選択基準

どこを深掘りして見せるかの優先順位：

1. **プロットの因果に触れるもの**（その設定がないと事件が成立しない）
2. **主人公の生活・職能に触れるもの**（毎話自然に画面に映る）
3. **感情の対比に使えるもの**（祭りの直後の惨劇、飢えの中の馳走）
4. その他——作っても本文には出さない（氷山の水面下）

- **焦点を作る**：1話・1場面で中心となるディテールを決める。複数を扱う場合も、何を印象に残すか主従を付ける。毎話同じ数の発見を義務化しない。
- **反復小道具**：単位・挨拶・食べ物・鐘など、毎話自然に登場する小さな世界要素を2〜3個決めて反復する。読者の身体に世界が馴染むのは、派手な設定ではなく反復する小物から。

## 4. 用語・固有名詞の出し方

- **文脈で意味が取れる形で初出させる**：「彼は腰の《ドルカ》を抜いた」→抜く動作が意味を教える。造語の直後に括弧で説明を入れる形式は没入を切る（どうしても必要ならルビや言い換えで一拍後に）。
- **語られない気配（allusion）は処理できる密度で置く**：「三百年前の白の夜以来、この鐘は鳴っていない」——説明せず置ける。個数を固定せず、同時に抱える未解決語の負荷を確認する。
- **地図・年表・用語集は「無くても読める」を保証した上での付録**とする。本文が用語集を前提にし始めたら開示設計の失敗と判断する。
- 会話での開示は**情報格差のある二人**を使う（新入り・異邦人・子供）。ただし主人公を万年質問役にしない——主人公が知っている領域では、読者だけが知らない状態を恐れず、体験で追いつかせる。

## 5. ダークファンタジーの没入（空気の作り方）

- **重さは禁忌と沈黙で作る**：登場人物が口にしない話題・触れない場所・夜にしない行為を設計する。「語られないこと」の輪郭が恐怖の形になる（ゴア描写の増量より効く）。
- **日常の摩耗を先に描く**：怪物より先に、痩せた畑・売られた娘・空の礼拝堂。世界の疲弊が日常レベルで示されていると、超常の恐怖が「その世界なら当然」の説得力を持つ。
- **恐怖は五感の欠落で**：見えない・聞こえない・匂いだけがする。情報を減らす方向の描写が、読者の想像力を恐怖の共犯にする。
- **希望の灯を画面に残す**：ダークの没入は「読者がまだ失いたくないもの」を画面内に置き続けることで維持される（worldbuilding-method.md §4 の希望残量）。灯が消えたら、次の灯を用意してから消すこと。
- **代償は遡って効かせる**：力の代償・呪いの進行は、使った「あの時」に遡って読者が気づく形（あの咳はそういうことだったのか）が最も深く刺さる。

## 6. 世界観開示の診断チェックリスト（相談で使う）

既存原稿・プロットの「世界観の見せ方」を診断するときの照合表：

- [ ] 作品の入口で、世界の説明が人物の行動や約束を長く止めていないか
- [ ] 新規固有名詞を、読者が文脈から区別・保持できるか
- [ ] 世界情報が「キャラの困りごと・行動」を経由して出ているか（裸の解説になっていないか）
- [ ] 必要な間隔で、読者が「発見」できる世界の手触りがあるか
- [ ] 反復小道具（単位・挨拶・食・鐘など）が決まっているか
- [ ] 深掘りディテールがプロットの因果に接続しているか（自慢のための考証になっていないか）
- [ ] （ダーク系）日常の摩耗→超常の恐怖の順で積んでいるか。希望の灯は画面に残っているか
- [ ] 地図・用語集なしで本文が読めるか

指摘は「直すと効く順」に2〜3点まで。全部は突きつけない（novel-plot-advisor と同じ運用思想）。

## 7. リポジトリ執筆への橋渡し（案内のみ）

相談の成果を実作に落とす段になったら：

- 世界設定の正本化 → `templates/world-bible.md` の三層（core／ondemand／log）へ。因果チェーンは core の該当ファイルに、地域・組織の各論は ondemand に収まる構造になっている
- 開示ペースの実装 → scene-card の「五感・must_use_facts」欄へ整理し、新規執筆は long-novel-orchestrator の通常入口へ
- 本スキルはここまで（記入・執筆はしない）。プロット側の相談が混ざってきたら novel-plot-advisor に切り替える
