# check-combat-equipment-terms：戦闘・装備用語監査

武器名の辞書引きだけで終わらせず、「どの部位を」「どの状態で」「どう操作したか」を一続きで照合する。正規表現で確定的な事故を先に拾い、武器形式や場面文脈が必要な判断を目視で補う。

## 実行モード

- 予防モード：新規本文を書く前に、登場装備の構造・状態・動詞を確定する。`write-episode` から呼ばれた場合の既定。
- 検査モード：既存本文を変更せず、誤用候補と根拠を報告する。検査・確認だけの依頼の既定。
- 修正モード：ユーザーが修正・改稿を明示した場合、本文と関係資料を最小差分で直して再検証する。`validate-episode` 修正モードから呼ばれた場合も選ぶ。

対象に戦闘・武器・防具・携行具が一つも登場しない場合は、用語監査を「対象なし」と記録して終了する。

## 1. 正本と参照範囲を決める

次の順で優先する。

1. ユーザーの明示指示
2. `world-bible/` と character-sheet に定義済みの作品固有仕様
3. 本Skillの `references/equipment-lexicon.md` にある構造基準
4. 専門語を避けた具体的な普通語

登場する装備に対応する節だけ `references/equipment-lexicon.md` から読む。正典に名称だけあり構造が未定義なら、専門語を推測で足さない。「柄」「刀身」「弦」「留め具」のように場面で確認できる部位へ下げて書く。

作品固有語は、定義と物理動作が整合していれば残す。現実語と同じ綴りを別の意味で使う場合は、初出または正典で差が読めるようにする。誤用を正典だからと反復しない。

## 2. 予防モード

### 2-1. 装備構造カードを作る

本文へ出す装備ごとに、資料から次の7項目を一行で確定する。

```text
装備名｜形式｜主要部位｜開始時の収納・装着状態｜使用時の遷移｜許容動詞｜助数詞・呼び分け
```

例：

```text
ヴェラの片手剣｜刃形式は未確定｜柄・柄巻き・鍔・刀身・鞘・柄袋｜柄袋を外し鞘へ収めて帯剣｜抜剣→使用→納剣→柄袋を掛ける｜柄を握る／鞘から抜く／刀身を点検する｜一振り
```

カードは内部設計であり本文へ貼らない。正典・current-state・scene-cardに根拠がある項目は、`write-episode` Step 1.5 の制約ブロックへ逐語引用する。根拠がない項目を新設定として断定しない。

### 2-2. 場面の状態遷移を通す

各装備について、必要な段階だけを次の順で確認する。

```text
携行・収納 → 取り出す／外す → 構える／装填する → 使用する → 解除・納める → 手入れ・再収納
```

前段を飛ばした動作を本文へ書かない。弓袋の中の弓の弦を弾く、柄袋を掛けた柄を握る、留め具へ固定していない弩を射つ、といった事故はこの段階で止める。

### 2-3. 語を決める

- 全体と部位を分ける。剣を見たのか、柄巻きの摩耗を見たのか、刀身の歪みを見たのかを曖昧にしない。
- 動詞は機構に合わせる。抜く、納める、引く、掛ける、つがえる、放つ、突くを交換可能な雰囲気語として使わない。
- 武器形式が未確定なら、形式依存語を避ける。両刃の可能性がある剣へ「峰」を足さない。
- 現場の俗称や人物固有の言い方は台詞で使えるが、読者に誤った物理像を渡す地の文では補助情報を置く。

## 3. 検査モード

### 3-1. 機械検出を先に行う

`run_terminal_command` で実行する。Pythonは `AGENTS.md` シェル実行の規約のインタプリタ順。横断検索は `grep`。

```bash
python3 scripts/combat_terms_check.py <対象ファイル>
```

複数話の横断監査では次を使う。

```bash
python3 scripts/combat_terms_check.py --all
```

`[NG]` は高確度の部位・動作・助数詞事故で、修正モードではゼロまで直す。`[警告]` は武器形式や場面意図を読まないと確定できない候補であり、機械置換しない。スクリプトが拾わない語も次の目視監査から除外しない。

### 3-2. 7軸で目視する

装備が現れる段落と、その直前に状態が変わった段落を読む。

1. 全体／部位：名称が指す範囲と、観察・損傷・操作の対象が一致するか
2. 収納／使用：袋・鞘・留め具・吊り具の状態で、その操作が可能か
3. 機構／動詞：抜刀、装填、射撃、防御、手入れの動詞が構造に合うか
4. 形式依存語：片刃・両刃、単材・複合、長柄・短柄など未確定の形式を先取りしていないか
5. 助数詞：武器、矢、人員、部品を取り違えていないか
6. 名称の連続：同じ物が説明なく柄／柄袋、籠手／手甲、槍／穂へ変わっていないか
7. 所持・損耗：前後の話と位置、数量、破損、紛失、回収、手入れが連続するか

用語に疑いがある場合は `grep` で `work/drafts/`、該当character-sheet、`world-bible/` の使用箇所を検索する。表記の多数決で決めず、最初に構造を定義した正典と実際の場面動作を照合する。

## 4. 修正モード

1. 誤った語を、場面が実際に示す全体・部位・状態へ置き換える。
2. 語だけでは物理像が直らない場合、取り外し・抜き出し・装填など欠けた状態遷移を短く補う。
3. 同じ誤用を `grep` で横断検索し、本文、scene-card、character-sheet、current-state、world-bibleの波及箇所を確認する。
4. 本文に合わせて関係資料を更新する。append-only台帳は過去行を書き換えず、訂正行を追記する。
5. `combat_terms_check.py` と `validate-episode` の全検証を再実行する。

単なる語の好み、時代差、翻訳差は誤用と断定しない。複数案が物理的に成立する場合は、作品内で最も既出の形式に合わせる。既出形式がなければ、最も専門語の少ない具体文を推奨する。

## 5. 報告する

- 実行モードと対象ファイル
- 登場装備と参照した正典
- 機械検出の `[NG]`・`[警告]` 件数とルールID
- 7軸の目視所見
- 修正モードでは、本文と関係資料の変更、横断検索、再検証結果
- 形式未確定・作品固有仕様など、残した判断と理由

「問題なし」は、機械検出ゼロだけでなく、対象装備の状態遷移と前後連続を目視した場合にだけ報告する。
