# 読者への約束フレームワーク（設計思想の正本）

商業Web連載の入口設計について、公開されている複数の創作論を横断して要約・再構成した設計モデル。特定の原文の転載ではなく、相談で使うための一般化された枠組みとして扱う。

> 適用範囲：主に、早い段階で明確な感情報酬を返す商業Web連載の設計モデル。ミステリー、ホラー、文芸、スローな没入型では、問い、恐怖、情緒、語りの声、認識変化も「約束」になる。以下の話数・配置は診断用の初期仮説であり、絶対条件ではない。

---

## 1. 基本原理：「面白さ」より「約束」が先

- WEB小説の読者は本文の面白さに到達する**前**に、タイトル→あらすじ→冒頭数行→1話末…と何度も離脱判断を繰り返す。第3話に強い見せ場があっても、第1話時点で「何を楽しみに読むか」が不明なら読者はそこまで来ない。
- 入口の仕事は設定の伝達ではなく**約束**＝「読み続ければ、あなたの欲しい気持ちよさが返ってくる」という予感を渡すこと。
- 約束の最小構成は3点：**主人公の立場／そこから何が変わりそうか／読者が期待していい気持ちよさ**。
- **謎と報酬の区別**：読者が知りたいのは謎そのものではなく「謎の先に自分の欲しい感情があるか」。謎だけの引きは弱い。
- 診断の単位を「才能・文章力」ではなく「入口の構造」に置く。どの部品（タイトル／あらすじ／1話の約束／2話の報酬／3話の勝利）が欠けているかを特定すれば、直す場所が決まる。

ジャンル別の「約束」の例：追放系＝苦しみの後の報われの予感／現代ダンジョン系＝数字や周囲の反応で主人公の価値が可視化される快感／ラブコメ＝関係が特別になっていく予感／ほのぼの＝安心して戻れる場所。

## 2. 第1話の設計

### 不遇・苦難の正しい用法
- 不遇は感情移入の装置として有効だが、**入口であって目的地ではない**。読者が見たいのは苦しみの時間ではなく、その後の報われ方。
- **追放（不遇）の理由は1〜2個に絞る**（能力の誤解・成果の横取り程度で状況理解には十分）。同義の罵倒の反復（「無能だ」「役立たずだ」「才能がない」…）は情報が増えず、しんどさだけが増える。
- 悪役の暴言を書き込むより、「主人公の立場が変わる瞬間」（外へ出た瞬間・新天地・出会い）を早く作る。
- 苦しめるなら同時に3点を置く：
  1. **主人公の価値**——自己申告でなく状況で見せる（抜けた後に周囲が困る／一人だけ正当評価している人物がいる）
  2. **反転の兆し**——移動・出会い・能力の微動・古巣側の異変
  3. **小さな安心材料**——折れていない心・一人の味方・行き先
- 報酬駆動型では、第1話の終わりに「ここからよくなる」という**小さな灯り**を置くと有効。暗い結末や不安で閉じる作品では、次に読む理由となる問い・危険・選択を残す。
- 逆方向の過剰補正にも注意：第1話で全部報わせる必要はなく、いきなり最強証明も不要。

### 設定説明の順番
- 設定説明が悪いのではなく**順番**の問題。「先に読む理由、そのあとに必要最小限の設定」。
- 設定を出す判定基準：「読者はこの説明を**読みたい状態**になっているか」。
- 説明は主人公の困りごとに絡めて出す（そのルールのせいで損している／価値が正当評価されない／後で反転しそう——という形で物語の動きに変換する）。魔法体系・ギルド制度を辞書のように並べる冒頭はNG。

### 第1話チェックリスト
1. 主人公の立場がすぐわかるか
2. なぜ不遇なのか短く伝わるか
3. 不遇が長引きすぎていないか
4. 報われる予感が第1話中にあるか
5. 次話で何が起きるか期待できるか

## 3. タイトル論

- タイトルは**設定を書く場所ではなく、読者に快感を約束する場所**。読者はタイトルで設定を理解しようとしておらず、「自分が読みたい話か・主人公はどんな立場か・どう気持ちよくなりそうか」を見ている。
- 点検フレーム：**立場・反転・報酬**の3要素。
  - 立場＝主人公の出発点（無能扱い／追放された／社畜だった／辺境・最弱・勘違い）
  - 反転＝そこからの転換（実は強かった／別の場所で評価される／ゆるく幸せになる）
  - 報酬＝読者が得る快感（見返す／解放される／成り上がる／溺愛される）
- **テンプレ語は感情を内蔵した共有インフラ**：「無能」＝見下され感、「追放」＝理不尽な切り捨て感、「社畜」＝疲労と解放願望。説明コストゼロで感情移入の足場を渡せる。テンプレ語の使用は個性の放棄ではない。
- ただし**テンプレ語単体では未完成**。「テンプレ語（立場）＋反転＋報酬」で1セット。独自性は共通の足場を置いた後に出す方が届く。
- **固有名詞・独自用語・能力名を「読む前の読者」に渡さない**。作者に大事な語ほど、未読者には無意味な文字列。設定を入れるなら「その設定が読者にどんな感情を返すか」までセットで見せる。
- 説明だけのタイトルは、立場・変化・報酬の**どれか1つを足すだけ**で改善する。

## 4. 序盤の維持設計

### 第2話の役割
- 第2話離脱の主因は、第1話末尾に「次のご褒美」（第2話で何が気持ちよくなるか）がないこと。
- 報酬駆動型の第2話は「説明する回」ではなく「**第1話で約束した気持ちよさを少し返す回**」として設計しやすい。説明は行動・変化に混ぜ、停滞して見えないようにする。
- NG典型：第1話で事件を起こした直後、第2話で世界観整理に入る（期待が止まる）。

### 3話以内の小さな勝利
- 報酬駆動型では、序盤の読者へ早めに小さな前進を返すと信頼を作りやすい。**3話以内**は1話の長さが一般的な連載での目安であり、固定期限ではない。
- 基本リズムの一例：**第1話で落とす→第2話で状況を動かす→第3話前後で小さく返す**。
- **勝利の5類型**：
  1. 能力の勝利（スキルが少し役立つ・別の場所で評価される）
  2. 評価の勝利（誰かの見る目が変わる——主人公が勝たなくても周囲の反応で読者は満足する）
  3. 数字の勝利（再生数・コメント・ランク・ステータスの微動。価値の変化が最も伝わりやすい）
  4. 関係性の勝利（距離が縮まる・自分だけが知る顔・軽い特別扱い）
  5. 居場所の勝利（安心できる場所・受け入れてくれる人）
- **「少し返す」原則**：全部返さない。序盤からの大きすぎる勝利（ボス討伐・最強証明）は後の展開を作りにくくするNG。
- 修正は大規模改稿不要——一言の評価・小さな成果・周囲の反応・次への予感を差し込むだけでよい。

### 10話チェックリスト
1. 主人公の立場が変わり始めているか
2. 小さな勝利がすでにあるか
3. 外部評価が動いているか
4. 次の大きな報酬が見えているか
5. 読者が応援したくなる余白があるか

（10話時点で反応がないとき「もっと派手に・もっと早く無双を」に走るのは誤診。必要なのは解決や派手さではなく「この先も気持ちよくなりそう」という期待の積み上げ。）

## 5. 話末の作法

- 話末には、次に動くもの、問い、危険、関係変化、報酬の予感など、その作品に合う継続理由を置く。
- 毎話を同じクリフハンガーや報酬予告で閉じない。余韻や一時的な完結が有効な回もある。

## 6. 運用思想

- **チェックリストは全達成不要**。5項目中1つ直すだけでも入口の印象は変わる。完璧主義で全面改稿を促さない。
- 助言では「どの1点を直すと最も効くか」の優先順位を必ず付ける。

## 7. AI執筆との関係（参考）

生成支援を使った小説の品質はモデル性能ではなく人間側の**設計力**で決まる。いわゆるポン出しの典型欠陥（キャラアーク欠如・テーマの説教化・伏線の不発・感情曲線のフラット化・文体ブレ）は、企画段階での変化定義・場面と行動によるテーマ暗示・シーンカードへの伏線明記・転換点の事前設計・スタイルガイド固定で消える。——この思想は本リポジトリの階層設計（plot→scene-card→本文）と同型であり、プロット相談の成果物を本リポジトリの templates/ に落とし込む説明をするときの橋渡しに使える。
