# Long Novel Orchestrator

長編の新規本文執筆における唯一の暗黙入口として、話をまたぐ順序と長期整合性を管理する。本文生成、3段バリデーション、台帳更新の実務は `write-episode` に委譲し、同じ手順をここへ複製しない。資料は `read_file` と `grep` で必要な範囲だけ読む。本文生成を `spawn_subagent` に渡さない（`AGENTS.md` 委譲）。

## 1. 依頼を正規化する

1. `AGENTS.md` を読む。
2. 対象が新規の1話、続き、複数話、アーク進行のどれかを確定する。
3. 既存本文だけの検査・修正なら `validate-episode`、相談だけなら対応する相談Skillへ引き継ぐ。
4. 話数未指定なら、既存ドラフト、`work/plot.md`、`work/continuity/current-state.md` から次話を特定する。
5. 「カクヨム向けに」「現在の傾向に合わせて」など市場方向と執筆が混在する場合は、`work/plot.md` の「読者への約束・投稿戦略ブリーフ」を確認する。未確定なら投稿先の時点付き情報を `novel-plot-advisor` で企画へ翻訳し、正典・主要筋を変える案だけ本文確定前にユーザーへ確認する。

## 2. 開始状態を監査する

読む順序は `AGENTS.md` の読み込み戦略を正本とする。ここでは対象範囲の開始判断に必要な差分だけを扱う。

`work/plot.md` では作品基本情報に加え、「読者への約束・投稿戦略ブリーフ」を読む。市場情報は毎話の流行追従ではなく凍結済みの企画意図として扱い、最新ランキングだけを理由に正典、人物像、主要筋を変えない。

不足が軽微で正典を変えない場合は、既存資料から保守的に補完して進める。人物の根幹、世界法則、主要筋などを変える補完が必要な場合だけ、本文確定前にユーザーへ確認する。複数話の連続執筆では、確認の要否と保留の扱いを `AGENTS.md` の「連続執筆モード」を正本として処理する。

## 3. 1話ずつ委譲する

複数話でも、次を1話ごとに完了してから次へ進む。

1. 対象話と、その話で主に変える状態、その変化に従属する差分を確認する。
2. `write-episode` に話数、依頼上の制約、必要な補完事項を渡す。
3. `write-episode` Step 5 の完了報告を受け取り、`AGENTS.md` の完了の定義をすべて満たしているか照合する。
4. 一つでも未完了なら次話へ進まず、同じ話の修復を優先する。
5. 完了した話の `current-state` だけを、次話の開始状態として扱う。

本文の場面設計や文体判断は `write-episode` と文体Skillへ委ねる。このSkillは本文を一括で先行生成しない。

## 4. アーク境界を監査する

`work/plot.md` で定義されたアーク境界では、[アーク境界監査](references/arc-checkpoint.md)を実施する。境界前でも、次の兆候があれば監査を前倒しする。

- 正典・時系列・情報格差の矛盾が疑われる
- 主要人物の目的や関係が大きく変わった
- 長期の約束や伏線を回収した
- 次話が重大な正典変更を必要とする

固定の話数間隔だけを理由に監査は行わない。重大な矛盾が見つかった場合は、次話の執筆より先に解決する。

## 5. 完了報告

各話について `write-episode` の証跡を要約し、複数話では話ごとの完了状況と最終 `current-state` を報告する。途中で停止した場合は、最後に完成した話と未完了の段階を明記する。連続執筆モードでは、`work/continuity/pending-decisions.md` に記録した保留判断の全件を完了報告に含める。
