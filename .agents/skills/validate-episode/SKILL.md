# validate-episode：既存本文の3段バリデーション

ユーザーが指定した対象はファイルパスまたは話数として解釈する。話数だけなら `work/drafts/` から該当ファイルを特定する。複数ファイルも処理できるが、結果はファイルごとに分ける。`episode<NNN>.txt` 以外の本文は単独短編として扱う。

## 実行モード

### 検査モード（既定・読取専用）

「検査して」「診断して」「チェックして」「問題を報告して」など、評価だけを求める依頼で使う。本文や資料を変更せず、違反箇所、根拠、修正方針だけを報告する。`ai-novel-detector` の診断は行うが、`humanize-ai-writing` による改稿は行わない。

### 修正モード

「修正して」「改稿して」「違反ゼロまで通して」など変更を明示した依頼、または `write-episode`／本文を新規保存した入口Skillからの呼出しで使う。意味の誤りと表記の[NG]を直し、humanize-ai-writing で必要な改稿をし、変更範囲を再検証する。ここでの違反ゼロは表記の[NG]と、行為者・対象の取り違えなどの意味の誤りである。文体警告の件数は目標にしない。

依頼が検査だけか修正込みか曖昧なら、検査モードを選ぶ。入口Skillが新規本文を保存した直後の呼出しは修正モードとする。

## 対象種別

- **長編1話**（`episode<NNN>.txt` または話数）：資料照合と `state_check.py` を通常どおり行う。完了判定は `AGENTS.md` の7項。
- **単独短編**（話番号なしの本文）：機械検出、全台詞監査、本文内部の視点・呼称・時系列、`ai-novel-detector`、修正モード時の `humanize-ai-writing` は長編と同じ。scene-card・character-sheet・pov-plan・continuity があれば照合し、なければ本文内部だけを見て未照合範囲を明記する。対象ファイル専用の状態差分・timeline行は必須としない。`state_check.py` はリポジトリ全体の台帳検査として実行するが、単独短編の完了判定をその exit code に結びつけない（正本は `AGENTS.md` の単独短編向け読み替え）。挿絵マーカー内のファイル名英字は半角英単語警告の意図的残置として裁定する。

## 1. 機械検出

`run_terminal_command` で実行する。Bashスクリプトは `bash scripts/...`。Pythonは `AGENTS.md` シェル実行の規約のインタプリタ順。

```bash
bash scripts/check.sh --strict <対象ファイル>
python3 scripts/normalize_blanklines.py --check <対象ファイル>
python3 scripts/repeat_check.py <対象ファイル>
python3 scripts/vocab_check.py <対象ファイル>
python3 scripts/cliche_check.py <対象ファイル>
python3 scripts/combat_terms_check.py <対象ファイル>
python3 scripts/state_check.py --strict
```

`repeat_check.py` は対象話と既存全話の12字以上の逐語一致を候補として出す。採否は `guidelines/02-narrative-craft.md` §5-3。機能する定型は残し、再警告を避けるときだけ `work/continuity/phrase-allowlist.txt` へ理由を書く。意味を変える変奏や、警告を消すためだけの登録はしない。検査モードでは allowlist を変更しない。

`vocab_check.py` は飽和注意語（`work/vocab-watchlist.tsv`）の話単位の出現を候補として出す。採否は `02-narrative-craft.md` §2-7。上限は割当量ではない。意図的な密度は除外欄へ理由を書いて再警告を避ける。検査モードでは watchlist を変更しない。

`cliche_check.py` は直訳クリシェ・感情ぼかし・圧縮癖のクラスタを候補として出す。採否は `guidelines/05-ai-guardrails.md` §3-4、5系統は §3-5。文脈判断は次節の `ai-novel-detector` が受け持つ。残す反復は `work/continuity/cliche-allowlist.txt` へ、その回の機能を書いて再警告を避ける。検査モードでは allowlist を変更しない。比喩候補の洗い出しが必要なら `scripts/metaphor_sweep.py` を使う。出力は候補であり、未実行を不合格にしない。

`combat_terms_check.py` は部位、収納状態、操作、助数詞に関する高確度事故を `[NG]`、武器形式や作品固有仕様を読まないと確定できない候補を `[警告]` として出す。戦闘・装備が登場する場合は `check-combat-equipment-terms` を同じ実行モードで使い、全体／部位、収納／使用、機構／動詞、形式依存語、助数詞、名称の連続、所持・損耗の7軸を目視する。検査モードでは報告だけ、修正モードでは `[NG]` をゼロにして警告を文脈判断する。

`state_check.py` は対象ファイル単位ではなくリポジトリ全体の台帳を照合する。本文ファイルと状態差分ファイルの対応、作中日時、現在状態、日付の正本（`world-bible/core/08-timeline.md §3`）との突合、伏線台帳、事実IDのずれを拾う。本文の内容には踏み込まないため、出来事と状態差分の意味的な対応、canon-log との整合、人物ごとの位置・所持品・負傷は次節の目視照合で確認する。

- 検査モード：exit code、[NG]、[警告]、空行検査を記録し、変更しない。
- 修正モード：対象本文の表記[NG]を、意味・視点・声を保つ最小差分で直し、`check.sh --strict` が exit 0 になるまで再実行する。repeat／vocab／cliche の候補は §3-4 で採否し、件数を合格条件にしない。`state_check.py` の[NG]は長編1話では必ず直す。単独短編では対象外（対象種別）とし、無関係な台帳欠落を直すために短編を止めない。
- 空行の自動正規化はしない。Webペースト由来の肥大を修正する明示許可がある場合だけ、段落構造を確認して適用する。
- 意図的な他言語表記など判断が必要な違反は、勝手に意味を変えず要判断事項とする。

## 2. 台詞を監査する

対象に台詞が一つでもあれば、[references/dialogue-semantic-audit.md](references/dialogue-semantic-audit.md) を読み、その手順で裁定する。この工程は `check.sh`、クリシェ検査、character-sheet の口調照合で代替しない。判定の正本は `guidelines/02-narrative-craft.md` §4-10 と `guidelines/06-revision-checklist.md` の B。前後二行や、一文への言い換えの一意性を合格条件にしない。

修正モードでは要修正だけを `humanize-ai-writing` へ渡す。役割説明を足して修理しない。

## 3. 視点・キャラ・情報格差・時系列を照合する

`guidelines/06-revision-checklist.md` のC〜Fを目視検査の正本とする。`work/pov-plan.md`、対象scene-card、登場人物のcharacter-sheet、`work/continuity/current-state.md`、canon-log、timelineの必要部分を読み、場面ごとに確認する。

- 視点運用が `guidelines/02-narrative-craft.md` §1 どおりである。場面内は一元、切替は境界、冒頭近くで誰の知覚か分かる。文数のノルマは置かない。他人の内面と、知り得ない情報を確定事実にしない。地の文の中立呼称は同 §1-5。切替は pov-plan の割当と一致する
- 台詞、作中引用、明示的な内心の一人称、二人称、呼称、語尾、禁則語がcharacter-sheetと正典に一致する
- 作中日時、位置、負傷、所持品、関係が前話終了状態と連続し、本文中の新事実が既存正典と矛盾しない
- 戦闘・装備が登場する場合、部位名、収納・装着状態、操作動詞、助数詞、損耗・回収が `check-combat-equipment-terms` の監査と正典に一致する
- scene-cardの「今回返す約束」が具体的な選択・結果・関係変化として読め、作品固有の核を市場語彙で上書きしていない

pov-planがなければhead-hoppingと本文内部の知識整合だけ、character-sheetがなければ一人称・呼称・語尾の内部的な揺れだけを検査する。continuityやtimelineがなければ本文内部の時系列だけを検査し、未照合範囲を明記する。scene-cardがなければ「今回返す約束」の項は対象外とし、開始・終了状態は本文内部で追えるかだけを見る。修正モードでも、資料不足を推測で正典化しない。

## 4. `ai-novel-detector` で診断する

1. `ai-novel-detector` の通常診断を行う。アーク境界・全編・話またぎの反復では Full Detect を使う。正典・視点・時系列・情報格差の照合は本Skillの前段が受け持つ。工程を分けるときだけ同Skillの引継ぎ票を使う。
2. 検査モードでは所見と修正方針を報告して終了する。本文は変えない。
3. 修正モードでは、高・中の意味の誤りと、`guidelines/05-ai-guardrails.md` §3-4 および地の文の骨格（`guidelines/02-narrative-craft.md` §2-8）で直すと決めた箇所を `humanize-ai-writing` へ渡す。好みの均質化はしない。説明文向けの文長や読点の個数を目標にしない。
4. 改稿後、変更範囲の表記検査と、`guidelines/06-revision-checklist.md` の確認範囲で照合する。
5. 変更箇所を一度再診断する。終了は同 06 の G-3。警告の件数を目標に巡回しない。

意図的に残す所見は、残置理由を報告する。

## 5. 補助計測

```bash
bash scripts/chars.sh <対象ファイル>
```

字数は完成後の実績値として記録し、上限・下限との比較や合否判定には使わない。文章のリズムは `cliche_check.py` が出す「リズム参考値」（文長CV、同一文末の最長連続、長断定文の最長連続）を読む。

**これらは合否条件ではない。** 閾値を設けて数値を目標にすると、場面の速度と無関係な文長調整が始まり、かえって平坦になる。使い道は次の2つに限る。

1. 場面の機能（加速・減速・対話）に対して文長のばらつきが逆方向になっていないかを見る。
2. 同じ話数帯の他の話と比べ、リズムの幅が単調な方向へ動いていないかを見る。

読み取った所見は、`ai-novel-detector` の診断と合わせて改稿の優先度づけに使う。数値そのものを報告の結論にしない。

## 6. 報告する

- 実行モードと対象ファイル
- 文字数と資料の有無
- 機械検出のexit code、[NG]、[警告]、空行検査。戦闘・装備がある場合は `combat_terms_check.py` のルールIDと7軸目視所見
- 台詞監査の抽出台詞数、要修正数、修正数、意図的残置数、未裁定数。残置には、場面のどこから関係が読めるか、または余白を残す理由
- 視点・キャラ・情報格差・時系列検査の場面数と所見
- `state_check.py` の結果と、リズム計測から読み取った所見
- scene-cardの目標・状態差分・読者への約束との照合結果（資料がなければ対象外と明記）
- 文体診断の初回所見
- 修正モードの場合：実施した差分、humanize-ai-writingの改稿結果、全再検証、最終診断
- 未解決事項とユーザー判断が必要な項目

検査モードでは「合格／要修正」を報告し、「違反ゼロに修正済み」とは表現しない。修正モードでは全段階が完了した場合だけ「修正完了」と報告する。

## 7. 完了条件

- 監査範囲の台詞は裁定済みで、未裁定がゼロである。
- 行為者・対象・態・否定・時点の取り違え、必要な関係の欠落、修正用の役割説明が残っていない。意図した余白は残置である。
- 表記の [NG] はゼロである。文体警告の件数は条件にしない。
- 修正箇所は `guidelines/06-revision-checklist.md` の確認範囲で再確認している。
- 修正モードでは、再抽出後の未裁定がゼロで、要修正が残っていない。検査モードでは要修正を位置と理由つきで報告している。
