# R18小説 文体レイヤー

## 役割

設計済みの成人向け場面を、日本語小説の本文として実現する。R18固有の語彙、感覚、会話、音、記号の描写体系だけを担い、物語上の関係性、行為の流れ、嗜好、主導権、結末を決めない。

本Skillの存在理由は、官能場面が「あっさりして駆け足」「婉曲表現だけでぼんやりする」「行為の羅列で人物が消える」というAI典型の失敗に落ちるのを防ぎ、読者が体感できる厚みのある描写を実現することにある。薄いか厚いか迷ったら、厚くする方向で書く。

優先順位は次のとおり。

1. ユーザーの明示と作品正典
2. 表記・視点・台詞・表現の採否は `guidelines/`（書式は 01、地の文の骨格は 02 §2-8、台詞の生成・短縮は 02 §4-10、採否は 05 §3-4・§3-5、確認範囲は 06）
3. 長編の配置・状態・成人向けの前提は `AGENTS.md`
4. `work/pov-plan.md`、character-sheet、scene-card、正典、および系統に応じた [style-corpus](references/style-corpus/INDEX.md)／[style-corpus-b](references/style-corpus-b/INDEX.md)
5. 本Skill。核イメージの設計既定は [shared-craft.md](references/shared-craft.md) §10

上位資料と衝突する技法は使わない。本Skillの各体系（フェーズ・配分・ビート密度など）は執筆判断を速く確かにするための設計既定であり、数合わせのノルマではない。scene-cardの指定、人物の声、場面の必然が優先する。

## 所有しない作業

- 新規話の資料読込、保存、3段バリデーション、台帳更新、完了判定は `write-episode` が所有する。
- 画像起点の単独短編の設計・保存と検証呼出しは `illust-r18-novel` が所有し、3段バリデーションの手順は `validate-episode` が所有する。
- 既存話の検査・改稿ループは `validate-episode` が所有する。
- AI的特徴の診断は `ai-novel-detector`、診断票に基づく改稿は `humanize-ai-writing` が所有する。
- プロット・関係性・場面の行為設計は作品のplot／scene-cardが所有する。
- 部位・体液・行為の言い換えは [references/vocab-remap.md](references/vocab-remap.md)。語彙表は [references/vocab/](references/vocab/)。必要なカテゴリだけ読む。

単独で呼ばれた場合も、本文案または文体改稿だけを返し、検証や台帳更新まで完了したと主張しない。

## 執筆前の必須境界

最初に [references/safety-and-inputs.md](references/safety-and-inputs.md) を読む。成人向けの前提は `AGENTS.md`。

- 成人向け依頼は全員を架空の成人（日本法18歳以上）として進める。年齢の逐次確認はしない。既成キャラクターは成人と定義し、原作設定には準拠させない。
- 許可か強制か、フィクション装置か現実寄りの関係かが場面として分かる。合意確認シーンは必須ではない。
- 視点人物、登場人物、開始状態、終了状態、場所、行為の範囲が分かる。
- ユーザーが未成年の性的生成を直接指示していない。現実の犯罪手口の具体化にならない。

直接の未成年指示、実在人物、犯罪how-toで止めない限り本文を書く。拒否・強制は依頼と文脈どおりに描き、実は合意だったと読み替えない。小柄・大柄は指定どおり書く。未成年記号にしない。平均体型へ均さない。

## モード選択

今回の依頼、scene-cardの「R18文体モード」、作品の既定の順で選ぶ。指定がなければ標準Webとする。

### 標準Web

地の文と会話を場面に応じて配分し、スマホで追いやすい短めの意味段落とビート構造で書く。♡・♥、擬音の独立行、台詞崩壊を作品指定の範囲でフルに使える、もっとも振れ幅の広い既定モード。なろう・カクヨム・ノクターン系の読み味。

詳細は [references/web-mode.md](references/web-mode.md)。

### 会話主体

会話、呼吸、擬音、短いト書きで進めるハイコンテクスト演出。発話タグに頼らない話者判別、崩壊時の残存アンカー、淫語のカテゴリ設計、コマ割り的な見せ場設計を使う。漫画原作・ASMR志向でも小説本文の体裁を保つ。

詳細は [references/dialogue-mode.md](references/dialogue-mode.md)。

### 文芸主体

自由間接話法による心理浸透、官能語彙の階調、核イメージの変奏、成熟した身体描写で書く。♡・♥などの記号強調は使わず、擬音は散文へ溶かし、昂りは語彙と文構造で描く。note・文庫調・女性向け官能の読み味。

詳細は [references/literary-mode.md](references/literary-mode.md)。

複数モードの要素が明示された場合は、主モードを一つ決め、追加要素だけを借りる。場面途中で無断に文体の基調を変えない。

## R18描写の共通体系

全モード共通の正本は [references/shared-craft.md](references/shared-craft.md)。擬音・喘ぎの語彙は [references/onomatopoeia.md](references/onomatopoeia.md)。系統の分け方は次。

- **A系**（宮廷・令嬢・標準Webの既定）：本文の呼吸は [style-corpus](references/style-corpus/INDEX.md)。技法ラベルは pattern-bank の該当節の `→` だけ。
- **B系**（現代・一人称受け）：本文の呼吸は [style-corpus-b](references/style-corpus-b/INDEX.md)。技法ラベルは pattern-bank の該当節の `→` だけ。A系の抜粋は読まない。

pattern-bank 三分冊は [buildup](references/pattern-bank-buildup.md)（設営〜挿入・系統の正本）、[climax](references/pattern-bank-climax.md)（高潮〜事後）、[voices](references/pattern-bank-voices.md)（voice card・特殊レイヤー）。通読しない。

読み方：選んだ系統の STYLE-NOTES と INDEX が示す抜粋 1〜2件。原文の長編ファイルは読まない。固有名詞と象徴フレーズは流用しない。♡配置は各 STYLE-NOTES §3。正書法の三点リーダ・ダッシュは guidelines が勝つ。B系の一人称原文は、新規の三人称場面では変換する。

骨子は次の12項目。

1. **ビート構造**：「動作または発話 → 視点人物が拾う感覚 → 反応 → 心理・判断 → 次の動作」を基本単位とし、序盤・中盤・クライマックス・事後でビート密度を変える。
2. **感覚描写の五層**：温度・質感・音・香り・視覚から各ビートに3層前後を織り込み、視覚偏重を避ける。体内感覚と対比を活用する。
3. **擬音4パターン**：独立強調行（頂点）／散文織り込み（導入・緩急）／リズム連鎖（持続）／衝撃音（突入・絶頂）を場面強度で使い分ける。
4. **♡エスカレーション5段階**：♡を使う作品では、導入→展開→高潮→絶頂→余韻でフェーズを飛び級せずに密度を制御する。濁点はフェーズ4限定。「！？」×♡で困惑と快感の同時表現ができる。
5. **台詞崩壊グラデーション**：キャラタイプ（高慢令嬢／天真爛漫／内気／クール敬語／お姉さん主導／嫌悪反転など）に応じ、途中切断・母音伸長・ひらがな化・実況化などの崩壊文法で段階的に崩す。崩壊しても人物の芯（自称や呼びかけ）を1つ残す。
6. **感情アーキテクチャ**：攻める側・受ける側それぞれの心理層を行為と並走させ、場面開始時と終了時で主導権の所在を変える。
7. **直接表現と文学的配分**：目安は直接60：文学40。ジャンルと投稿先で70:30〜40:60に振る。全編婉曲で覆わず、直接語彙は感情・文脈と結合させる。
8. **射精3要素**：予兆（体内感覚）→擬音→着弾感覚（温度・深度・量・受け手の反応）を揃え、予兆を省いて突然射精しない。
9. **事後の人間性回復**：絶頂後はscene-cardの終了状態に合わせて「人」に戻す。強制場面を甘えへ均さない。
10. **核イメージ**：場面を束ねる比喩は核を変奏するのを既定にする。補助は必要なときだけ足す。採否は 05 §3-4。比喩は視点人物の生活・職業・文化から選ぶ。
11. **短文宣言と対比構造**：転換点はダッシュ＋短文で刻む。高貴×淫靡、理性×本能、体格差などの対比を軸に置く。
12. **合理化口実とシーン継続装置**：「研究だから」等の合理化フックを事前装填して崩壊を映えさせる、回復魔法等の設定で連戦を可能にする、などの装置はscene-cardまたは作品設定にあるものだけを使う。

## 上位規約との整合

- 地の文を書く・言い換える直前は `guidelines/02-narrative-craft.md` §2-8。接触、体内感覚、核イメージ、場面が転じる対比は、説明文の比喩解体で平文化しない。残す条件は同節。
- 視点方式は `guidelines/02-narrative-craft.md` §1 と pov-plan。指定がなければ場面内は三人称一元、境界で交替できる。既存の一人称を改稿で三人称に変えない。参照実例が一人称でも、三人称の新規場面へ呼吸を移すときは人称を場面の方式に合わせる。切替の文数ノルマは置かない。
- 地の文の人物名は中立呼称にする（正本 `guidelines/02-narrative-craft.md §1-5`。台詞・引用・明示的な内心はキャラシートと正典に従う）。
- 台詞と明示的な内心の一人称・呼称・語尾・禁則語はcharacter-sheetを維持する。高揚を理由に別人の声へ変えない（崩壊はその人物の声の崩れとして書く）。
- 三点リーダは「……」、ダッシュは「――」（U+2015）に統一し偶数個。参照実例の「——」「──」表記は本文へ持ち込まない。
- 空行は `guidelines/01-writing-rules.md` §7 に従い、緩急の演出として使う。ビート間の間は空行1〜3行の範囲で作り、4行以上連続させない（`normalize_blanklines.py --check` の検出対象）。空行数を固定の強度段階表にしない。
- 身体の位置、向き、接触、衣服、小道具を連続させ、物理的に飛ばさない。
- 拒絶、救援、沈黙、凍りつき、身体反応を合意へ読み替えない。依頼が強制・非合意ならそのとおりに描く。
- scene-cardにない行為、嗜好、関係変化、妊娠、結末をSkill都合で追加しない。絶頂・射精・主導権反転・事後はscene-cardの展開範囲内で、本Skillの体系を使って厚く描く。
- 場面終了後は `narrative-style-web-novel` の元の文体モードと記号密度へ戻す。R18場面だけで使った記号・語彙・段落密度を後続場面へ漏らさない。

## Pre-write protocol（内部処理。出力に含めない）

本文へ入る前に次を内部で確定する。

```
視点（pov-planの方式と誰の視点か。割当と一致）
関係性と感情状態（初対面・恋人・既婚・主従・特殊フレーム等）
シーンの位置づけ（関係の進展／崩壊／契機／ご褒美回 等）
欲求または回避（駆動力）と障害（葛藤）
変化（シーン終了時に何が変わるか・主導権の初期配置と反転先）
モード（標準Web／会話主体／文芸主体）と直接：文学の配分
核イメージ（比喩モチーフ）＋補助
♡・記号の使用有無とフェーズ設計（使う作品のみ）
受け側のキャラタイプと崩壊パターン・残存アンカー
射精・絶頂の有無（scene-cardの範囲内）と事後の人間性回復の型
```

シーン構成は導入（場・温度・緊張・フック）→展開（積み上げ）→クライマックス（要約せず体験として描く）→余韻（回復・変化・次への含意）の4部を基本とし、scene-cardの開始・終了状態に合わせる。

## 執筆ワークフロー

### 新規生成

1. 執筆前の必須境界とPre-write protocolを確定する。
2. 選んだモードのreferenceと `shared-craft.md` を読む。A系なら [style-corpus/STYLE-NOTES.md](references/style-corpus/STYLE-NOTES.md)、B系なら [style-corpus-b/STYLE-NOTES.md](references/style-corpus-b/STYLE-NOTES.md) と該当抜粋 1〜2件を先に読む。擬音・喘ぎは `onomatopoeia.md`、局面の技法ラベルは pattern-bank の該当節だけ（設営〜挿入は buildup、高潮〜事後は climax、声は voices）。地の文の部位・行為語は [vocab-remap.md](references/vocab-remap.md) の該当カテゴリだけ（挿入〜抽送なら S1/S3/S9/P1/P2/P7）。
3. 場面単位で設計を確認しながら本文を書き、話全体のリズムを最後に統合する。
4. [references/checklist.md](references/checklist.md) の出力前チェックで自己検証する。

### 文体改稿

既存本文を改稿するときは、人物、許可／強制の範囲、出来事の順序、結末、正典を固定する。

1. 指定モードと現在の本文との差、および共通体系に照らした不足（心理の並走、感覚層、擬音の連動、崩壊の段階、射精3要素、事後回復）を特定する。
2. 描写の厚みを増す方向を基本に、語彙、段落、会話、音、比喩を必要箇所だけ変更する。冗長な反復や定型表現は削る。
3. 身体位置、POV、キャラクターの声、許可／強制の読みやすさを再確認する。

展開変更が必要なら本文へ反映せず、plot／scene-card側の判断として親ワークフローへ返す。

### 分析・強化（明示依頼時のみ）

既存R18シーンの分析と改善提案を明示的に求められた場合は [references/scene-analysis.md](references/scene-analysis.md) のフェーズ1〜4に従う。リポジトリの執筆ワークフロー内では、検査・改稿ループの統括は `validate-episode` が所有する。

## 文体固有の自己点検

詳細は [references/checklist.md](references/checklist.md)。最低限の骨子：

- 成人向け依頼として進めているか。未成年の直接指示がないか。許可／強制と装置・関係が場面として分かるか。挿絵短編では先頭注意書きでフィクション・全員成人を示し、作中の年齢確認を義務としないか。
- 視点、正典、人物の声、行為範囲を変えていないか。地の文の固有名が中立呼称か。
- 選んだモードが場面全体で判別でき、身体の位置・衣服・小道具・時間の連続性を追えるか。
- 行為があっさり・駆け足になっていないか。心理が行為と並走し、感覚が各ビートに3層前後あるか。
- 全編婉曲でぼんやりしていないか。直接語彙が感情・文脈と結合しているか。
- ♡・濁点・擬音・崩壊がフェーズの段階を踏んでいるか（飛び級・数合わせの反復がないか）。
- 射精がある場合、3要素が揃っているか。絶頂後に人間性回復があるか。
- 段落と空行が意味段落と緩急に従い、空行4行以上の連続がないか。
- scene-cardにない行為、関係変化、結末を追加していないか。
