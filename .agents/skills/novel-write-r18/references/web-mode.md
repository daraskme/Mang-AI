# 標準Webモード

地の文と会話を両方使い、スマホで追いやすいR18小説本文にする。なろう・カクヨム・ノクターン系の読み味を既定とし、3モードの中でもっとも振れ幅が広い。文芸寄りのトーンを求められたら段落を伸ばし空行と記号を絞ってよい（振り切るなら文芸主体モードへ）。

共通体系（ビート構造・感覚5層・射精3要素・事後回復など）は `shared-craft.md`、擬音・♡の語彙は `onomatopoeia.md`、場面タイプ別実例は pattern-bank 三分冊（buildup／climax／voices）を正本とする。本ファイルはWebモード固有の運用だけを扱う。

## 1. 段落とテンポ

- 1段落1〜3文を基本に、動作、反応、判断、会話のまとまりで区切る。長い解説段落を作らない。
- ビート間は空行1〜3行で「間」を作る（4行以上は連続させない。空行数を固定の段階表にせず、緩急で使い分ける）。
- 連続する会話の応酬は詰め、沈黙や転調だけを意味のある空行で示す。
- 短い段落を見せ場に集中させ、全段落を一文へ揃えない。
- 短文ビート反復（「ゆっくり、押して。ゆっくり、引いて。」）で律動を作れる。多用しない。

## 2. 擬音の運用

4パターン（独立強調行／散文織り込み／リズム連鎖／衝撃音）を場面強度で使い分ける。語彙と場面別マッピングは `onomatopoeia.md`。

- **独立強調行はビートの頂点に置く**。前後を空行で挟み、句点か感嘆符で締める。挿入の瞬間は散文織り込みにして、受け手の反応で時間を伸ばす方が効く。
- 同種の音の濁点と長音を少しずつ増やすことで、強度上昇を視覚化できる（「ちゅぷ……」→「ぢゅるるっ……」）。
- 同じ音を4行以上連打しない。音を増やすより人物の認識または動作結果へ移る。
- 擬音は必ず地の文の動作と連動させる。記号の羅列にしない。

## 3. ♡と記号

♡・♥は作品の既定または依頼にある場合だけ使う。使う場合は5段階エスカレーションで密度を制御する（詳細は `onomatopoeia.md` §♡体系）。

- A系の♡は [STYLE-NOTES §3](style-corpus/STYLE-NOTES.md)（頂点の擬音独立行へ♡可）。B系は受け側の台詞内のみ。攻める側と擬音以外の地の文には付けない。
- 濁点（゛）は絶頂フェーズ限定。フェーズを飛び級しない。
- 「！？」×♡で「望んでいない／驚いている／でも感じている」の三重感情を記号だけで伝えられる。受け側の台詞に限り、序盤は単発、高潮以降で強調形を解禁する。
- 一作品・一人物で記号の種類（♡か♥か）と意味を安定させる。
- 記号数を強度メーターにせず、語彙、呼吸、動作、反応の変化と組み合わせる。

## 4. 発話の変化

台詞崩壊グラデーション（`shared-craft.md` §4、実例は `pattern-bank-voices.md` §11 voice card）をキャラタイプに合わせて設計する。

- character-sheetの一人称・語尾・禁則語を起点に、その人物の通常時との差を書く。
- 崩れを一方向に進めず、取り繕い、沈黙、言い直しを混ぜる。
- 言葉が崩れても、話者と許可／強制の状態を読者が追えるようにする。

## 5. Webモードの見せ場設計

- 導入で合理化口実または関係の緊張を1つ仕込み、クライマックスでそれが崩れる（または回収される）ようにする。
- パワーダイナミクスの反転点は短文宣言で刻む。
- 射精は3要素（予兆→擬音→着弾）＋宣言・反応台詞の5層構造を標準形とする。強制場面で許諾台詞を足さない。
- 事後は人間性回復＋関係性確定＋次への含意で8〜15行相当を割く。

## 6. 確認

- 記号や擬音を除いても、人物と状態変化が読めるか。
- 段落、短文、記号が均一な型になっていないか。
- 行為だけでなく、視点人物の判断と相手の応答が進んでいるか。
- あっさり・駆け足になっていないか（各ビートに感覚3層前後、心理の並走があるか）。
- 一般文体へ戻る境界が自然か。
