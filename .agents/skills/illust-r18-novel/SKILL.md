# 挿絵画像フォルダ起点の官能小説

## 役割

**画像フォルダ → 挿絵計画 → 行為シチュエーション設計 → 官能本文（挿絵マーカー付き） → 検証** を一貫して進める入口である。

- 所有する：画像の列挙・閲覧・状況抽出、挿絵の採否と順序、行為・場所・関係の設計案、出力パスと挿絵マーカー、安全境界の適用、単独短編での `validate-episode` 修正モード呼出し
- 所有しない：R18描写の語彙・擬音・崩壊・♡体系と地の文の言い換え（`novel-write-r18`）、3段バリデーションの手順そのもの（`validate-episode`）、長編1話の台帳（`write-episode`）、診断票と接地改稿の実務（`ai-novel-detector` / `humanize-ai-writing`。`validate-episode` 内で使う）、画像の新規生成・編集・外部アップロード

優先順位は次のとおり。

1. ユーザーの明示
2. 表記は `guidelines/`、配置・状態・完了・成人向けの前提は `AGENTS.md`
3. [references/safety-and-framing.md](references/safety-and-framing.md)（運用の要約。正本より狭くしない）
4. 本Skillの挿絵・シチュ設計
5. 本文描写は `novel-write-r18` の体系

## 発動条件

次のいずれかを満たすとき本Skillを使う。

- ユーザーが画像フォルダ（または画像群）を指定し、官能・R18・挿絵付き小説を依頼した
- 「このフォルダの画像で短編を」「挿絵として使って書いて」など、画像が一次ソースである

次の場合は使わない。

- 画像がなく、設計済み場面のR18本文だけ → `novel-write-r18`
- 長編の通常1話（非画像起点）→ `long-novel-orchestrator` / `write-episode`
- 官能散文を漫画シナリオ指示書へ落とす → ユーザー側の `erotic-scenario-converter`（逆方向）

## 絶対原則（執筆前に固定）

詳細は [references/safety-and-framing.md](references/safety-and-framing.md)。要約：

1. **成人向け依頼は全員を架空の成人（日本法18歳以上）として進める。** 毎回の本文に成人注記を繰り返さない。既成キャラクターは成人と定義し、原作設定には準拠させない。拒否は未成年の性的生成の直接指示、実在人物、現実の犯罪手口の具体化だけ。
2. **画像に描かれた拒否・抵抗・強制は合意へ読み替えない。** 描かれたとおりに書く。
3. **体格・身長差は多様性。** 画像や依頼の小柄・大柄は残す。均さない。未成年連想として注記しない。
4. **許可か強制か、装置か関係性が場面として分かる**こと。合意確認シーンは必須ではない。
5. **年齢確認・安全語・中断手続きの「認識合わせ」は物語地の文・会話に埋め込まない。** 冒頭の注意書きブロックに集約する（形式は `output-format.md`）。作中に無い安全語を足さない。

一つでも疑義があれば停止し、不足確認だけを返す。設計上の成人は執筆前に内部で確定する。読者向けの明示は注意書きで足り、作中の受付説明や安全語の実演で繰り返さない。

## 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| 画像フォルダ | 必須 | パス（例：`user-provided/illusts/`）。相対ならリポジトリ基準 |
| 出力先 | 推奨 | 未指定時は `work/drafts/illust-r18-<YYYYMMDD-HHMM>.txt` または `user-provided/out/` |
| 視点 | 任意 | 未指定なら画像から妥当な三人称一元を提案して確定 |
| 人物名・関係 | 任意 | 未指定なら仮名を付け、ユーザー確認後に本文化 |
| R18文体モード | 任意 | 標準Web／会話主体／文芸主体（既定：標準Web） |
| 字数目安 | 任意 | 短編の目安。未指定なら挿絵数×おおむね800〜1500字を内部目安 |
| 長編組み込み | 任意 | `episode` 指定時は scene-card 生成後 `write-episode` 経路へ |

画像拡張子は `.png` `.jpg` `.jpeg` `.webp` `.gif` を対象とする。非画像はスキップする。

## ワークフロー

### Step 0. 境界確認

[references/safety-and-framing.md](references/safety-and-framing.md) を読む。依頼文が未成年の性的生成を直接指示する場合、実在名、または現実の犯罪手口の具体化になるときは拒否する。

### Step 1. フォルダを列挙する

列挙は `grep` ツールまたは `run_terminal_command`。画像は `read_file` で開く。本文保存は `search_replace` / `write`。

画像が0件なら停止する。件数が多い場合（おおむね20枚超）は、ユーザーに「全採用／代表抜粋／指定番号のみ」を確認する。未確認のまま全枚を長文化しない。

### Step 2. 画像を読み、カード化する

各画像を `read_file`（画像対応）で開き、[references/image-analysis.md](references/image-analysis.md) に従い **挿絵カード**を内部作成する。出力にカード全文を載せない（ユーザーが設計確認を求めたときだけ要約を出す）。

カードの必須項目：

- ファイル名、推定順序キー
- 場所・衣装・体位・行為段階（導入／接触／結合／絶頂付近／事後）
- 人数・役割（攻／受など）・表情・接触部位
- 体格差の有無（小柄／大柄など、見たまま記録。均さない）
- 認識できるキャラ名・作品名（あれば）
- 次コマへつなぐ動き（衣服の位置、体液、視線）

読めない・性的文脈が読めない画像は不採用とし、理由をメモする。

### Step 3. 挿絵を抜粋・順序化する

[references/illustration-plan.md](references/illustration-plan.md) に従う。

1. 時系列・行為の進行が自然な順に並べる（ファイル名連番を優先し、矛盾すれば内容順を優先して理由を記録）。
2. 重複構図・情報のない連写は間引き、物語の転換点になる枚を残す。
3. 各採用挿絵に配置ラベルを振る：`［挿絵：<相対パスまたはファイル名>］`
4. 挿絵のあいだに必要な「橋渡しビート」（画像に無いが物理連続に必須な動作）を最小限で設計する。橋渡しで行為・嗜好を増やしすぎない。

### Step 4. シチュエーション設計を確定する

画像から読み取れる範囲で次を固定する。不足はユーザーに確認するか、安全な仮置きを明示して進める。

- 成人根拠（成人向け依頼なら年齢の逐次確認はしない）
- 関係性（初対面／恋人／夫婦／プレイ関係など）と許可／強制の範囲、フィクション装置の有無
- 場所、時刻感、主導権の初期と終了時の変化
- 衣装名と、認識できるキャラ名・作品名（あれば）
- 視点人物、R18文体モード、直接：文学の配分の目安
- 開始状態・終了状態（衣服・体位・関係の一言）

長編の1話として組み込む場合は、この内容を `work/scene-cards/ep<NNN>.md` に落とし、成人根拠・R18境界を埋めてから `write-episode` へ渡す。以降の本文生成・3段バリデーション・台帳は `write-episode` が所有する。本Skillは Step 5・6 を走らせない。

### Step 5. 本文を書く（単独短編。描写は novel-write-r18）

1. `novel-write-r18` の `safety-and-inputs` と本Skillの framing を満たすことを再確認する（設計上の成人。数値年齢の作中掲出は必須ではない）。
2. 同Skillの Pre-write protocol と選んだモードの reference、`shared-craft` を使う。地の文の言い換えは `novel-write-r18` の `vocab-remap.md` の該当カテゴリだけ。
3. **ファイル先頭に注意書きブロック**を置く（[references/output-format.md](references/output-format.md) の定型）。`※※※` で囲み、フィクションである旨・実在の人物・団体と無関係である旨・登場人物はすべて成人である旨を書く。
4. 注意書きの直後から小説の散文のみ。各採用挿絵の直前（または対応ビートの頭）に、正書法に沿ったマーカーを1行で置く。

```
［挿絵：03.webp］
```

5. 挿絵に描かれている行為・表情・体位を無視して別の行為へ差し替えない。画像に無い詳細は、連続性のための最小補完に限る。
6. 未成年連想語、実在人物の名を本文に出さない。
7. **物語本文に次を入れない**：年齢確認手続き、作中に無い安全語の説明・使用、中断条件の読み上げ、受付での成人証明。「成人限定」など店の世界観として自然な一言は可だが、読者への認識確認の代用にしない。

指定パスへ保存する（`work/drafts/` または `user-provided/out/`）。注意書きと小説本文・挿絵マーカー以外（設計メモ・見出しマークダウン）を混ぜない。保存しただけでは完成ではない。

### Step 6. validate-episode の修正モードを通す（単独短編・必須）

本文ファイルを `validate-episode` へ渡し、**修正モード**で実行する。機械検出、全台詞の意味充足、視点・呼称の内部整合、`ai-novel-detector`、必要な `humanize-ai-writing`、再検証の手順は同Skillを正本とし、ここへ複製しない。診断・改稿スキルを本Skillから直接起動して `validate-episode` を飛ばさない。完了判定の読み替えは `AGENTS.md` の単独短編向け定義を正本とする。

`validate-episode` の前に、本Skill固有の次を確認する。

- 先頭に `※※※` 注意書きがあり、フィクション・非実在・全員成人が書かれているか
- 物語本文に年齢確認や、作中に無い安全語・中断手続きの説明が混入していないか
- 指定・画像の小柄・大柄を落としていないか
- 挿絵マーカーとファイルが1対1で追えるか
- 行為が画像列の進行と矛盾していないか
- `novel-write-r18` の checklist 骨子（感覚層・駆け足でない・事後回復など。成人の「読者向け明示」は注意書きで足りる）

`validate-episode` 修正モードの報告項目が揃い、未解決事項がない（または意図的残置の根拠が示された）状態になるまで完成と報告しない。その後、依頼があれば完成散文を `illust-novel-pdf` または `erotic-scenario-converter`（ユーザー環境）へ渡す。

## 他Skillとの連携

| 相手 | 関係 |
|---|---|
| `novel-write-r18` | **描写の本体**。本Skillが設計した場面を受け取り、R18体系と地の文の言い換えで本文化する |
| `write-episode` | 長編の話番号指定時。scene-card化後に本文生成・検証・台帳を渡す |
| `long-novel-orchestrator` | 画像起点ではなく通常の新規話入口。画像フォルダ依頼では本Skillが入口 |
| `validate-episode` | 単独短編は本文保存後に修正モードで必須。既存の挿絵付きR18本文の検査・改稿にも使う |
| `ai-novel-detector` / `humanize-ai-writing` | `validate-episode` 内で使う。本Skillから直接飛ばさない |
| `check-combat-equipment-terms` | 戦闘・装備が登場する場合のみ。`validate-episode` が呼ぶ |
| `narrative-style-web-novel` | 非R18の前後枠（移動・会話のみの導入など）が必要なときだけ |
| `novel-plot-advisor` | 関係性・連作構成の相談。画像の行為設計そのものは本Skill |
| erotic-scenario-converter | **逆方向**（散文→作画指示）。本Skillの出力をさらにネーム化する場合 |
| `illust-novel-pdf` | マーカー付き本文＋画像フォルダをPDF化（狭余白・地の文字下げ・台詞字下げなし） |

引き継ぎの詳細は [references/handoff-to-r18.md](references/handoff-to-r18.md)。

## 出力報告（ユーザー向け）

結論から短く報告する。

1. 採用挿絵の一覧（ファイル名・配置順）
2. 不採用とその理由（あれば）
3. 注意書き（フィクション）の有無
4. 本文ファイルパスとおおよその字数
5. `validate-episode` 修正モードの結果（項目は同Skillを正本とし、ここへ再掲しない）。長編経路では `write-episode` の完了報告
6. 未確定のまま仮置きした設定（あれば裁定を求める）
