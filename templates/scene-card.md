# シーンカード（1話単位の執筆設計）テンプレート

1話分の本文を書く**直前**に埋める設計シート。執筆中の `<beat>` インライン記述を置き換え、`scene-cards/ep<N>.md`（作品ディレクトリ直下）として作品ごとに保管する。

**配置**：`work/scene-cards/ep<NNN>.md`。Grokは各話の執筆前に当該カードを読み、本文確定後も一次資料として保存する。

---

## このファイルの目的

「Grok に1話を書かせる」ときの**局所設計を1ファイルに集約**する。これによって：

1. 「いま書く章で読者に渡すもの」を**書き始める前に明文化**する（曖昧な「整える章」防止）
2. 必要な previous_facts・伏線・開示禁止情報を設計段階で選別する
3. 出力後に**シーンカードと本文を照合**して、設計通りに書けたか検証できる
4. 50万字超でも**1話あたり300〜800字程度**の設計コストで済む（メイン作業は本文）

---

## カード本体（埋める）

各章でコピーして使う。

```yaml
---
ep_no: 1                            # 通し番号
ep_title: 「（章タイトル）」
beat:                               # 作品が採用した構造上の位置。転換点名
arc: 第一部                          # plot.md のアーク名
plot_position: "きっかけ"            # plot.md のどこに対応するか
reader_effect:                      # 中心となる読者効果。固定の感情一覧から選ぶ必要はない
target_chars_min:                   # plot.md §作品基本情報の目安と許容幅に従う
target_chars_max:
---
```

## 2. 登場キャラ（このシーンに出る人物）

各キャラに**今の状態**を1〜2行で。長期的な設定は character-sheet を参照。

| キャラ | 出番タイプ | 今の状態（このシーン直前） |
|---|---|---|
| （視点キャラ）| 主役 | 例：直前の戦闘で右腕を負傷／甘味は欠落のまま |
| （カウンターパート）| 重要 | 例：消耗が顕著・頬がやつれ始めている |
| （サブ1）| サブ | 例：班員として帯同。船酔い気味 |

---

## 3. シーンゴール（読者にこの章で渡すもの）

**1〜3行で「何を読者の手元に置いて章を終えるか」**を書く。

```
（例：恒一が9層の楔の前で立ち尽くし、ユミナの腕の刺青が呼応するのを見て、
ユミナの代償構造の片鱗を理解する。読者には「ここから先は二人の問題ではなく、
世界の構造の問題である」という認識を渡す）
```

| 読者への約束との接続 | 値 |
|---|---|
| 今回返す約束 | （plot.md §読者への約束・投稿戦略ブリーフから、今回実際に返すもの）|
| 今回は返さず強める圧力 | （先送りの理由と、読者が受け取る新しい材料）|
| 作品固有の核 | （市場傾向へ寄せても変えない人物・関係・問い）|

## 4. 対立軸（GMC: Goal / Motivation / Conflict）

シーンを駆動する人物の欲求と、それと両立しない利害・条件を書く。対立は敵や妨害に限らず、時間、資源、誤解、関係、二つの守りたいものの衝突でもよい。

| 項目 | 値 |
|---|---|
| Goal（このシーンで主人公が達したいこと）| |
| Motivation（なぜそれを達したいのか）| |
| Conflict（何が阻んでいるか）| |
| 結末（達成・失敗・撤退・先送り のいずれか）| |

---

## 5. 章前後の状態差分（必達）

**章開始時 → 章終了時**で、読者が追える状態を少なくとも一つ変化させる。外面・内面・関係の全軸を毎話動かす必要はない。

| 軸 | 章開始時 | 章終了時 |
|---|---|---|
| 外面（場所・所有・身体・立場）| | |
| 内面（理解・決意・感情）| | |
| 関係（誰と誰の距離・信頼）| | |

全軸が同じに見える場合は、認識、選択肢、圧力、意味のどれが変わったか説明できるか確認する。説明できなければ削除または統合候補。

## 6. 進捗チェック（最低1つ達成）

このシーンで以下のいずれかを達成する：

- [ ] 情報開示（読者が知らなかった事実が判明）→ 内容：
- [ ] 関係変化（キャラ間の関係が変わる）→ 内容：
- [ ] 位置・期限・危険の変化（物理条件が以後の選択を変える）→ 内容：
- [ ] 決断（主人公が選択する）→ 内容：
- [ ] 喪失または獲得（何かを失う／得る）→ 内容：

この話で変わった状態を受け取り、次に残る圧力または余韻へ着地する。場面に合う効果を選び、一覧にないものも使える。

- [ ] 次話への問い：（具体的な台詞・行動）
- [ ] 異常事態の発生：
- [ ] 選択の提示：
- [ ] 達成・安堵と新しい代償：
- [ ] 関係または既知情報の意味の反転：
- [ ] 余韻・未完了の行動：

`world-bible/log/canon-log.md` から**当該シーンに関連する事項のみ抜粋**。多すぎても thinking を引きずる。**5〜15項目を目安**。


## 9. 開示禁止情報（このシーンでは出さない）

**未回収の伏線で、当該シーンでは触れない／触れるが核心は出さない**項目。これを明文化することで、Grok が知っている設定を「先に出してしまう」事故を防ぐ。

```
- 楔の真の機能（旧き者の封印維持）は第109話で初めて開示。本章は「何かがある」止まり
- ユミナがリライトに使った魔力の半分以上を消耗していることは第92話で告白。本章では未開示
- マハ（旧き者）の名は第110話で初登場。本章では「古代の番人」「眠るもの」表現に留める
```

## 11. 感覚・具体物の素材

場面の危険、欲求、記憶、判断、生活に効く素材だけを選ぶ。全欄を埋めず、五感を同数配置しない。

| 感覚 | このシーンで使う素材 |
|---|---|
| 嗅覚 | （例：地下水と鉄錆の匂い）|
| 味覚 | （食事描写があれば固有食材名で）|
| 触覚 | （例：石壁の冷たさ・ユミナの手の薄さ）|
| 温度 | （例：9層の冷気・吐息の白さ）|
| 湿度 | （例：水滴が落ちる音）|
| 聴覚（環境音）| （例：地脈の低い唸り）|

**身体反応**：必要なら、人物の体質・抑制・状況に固有で、次の行動や判断へつながるものを書く。

## 13. 文体・トーン指示

| 項目 | 値 |
|---|---|
| 章全体のテンポ | 緩／中／急（戦闘・追跡は急、内省は緩）|
| 文体モード | plot準拠／地の文主体／会話主体／混合 |
| R18文体モード | 非R18／標準Web／会話主体／文芸主体（R18を明示した場面だけ指定） |
| R18境界 | 全参加者の18歳以上の根拠／許可または強制の範囲／フィクション装置の有無（非R18では「対象外」） |
| 段落リズム | 意味段落を基本に、加速・余韻・転調を置く箇所を具体的に指定 |
| 会話と地の文 | 会話で進める対立と、地の文で接地する位置・身体・結果を指定 |
| 比喩・感覚 | 視点人物の経験に属する核イメージや、優先する感覚があれば指定 |
| 場面転換 | plotで固定した記号／意味のある空行／なし（連続シーン）|

## 14. Grokへの引き渡し

本カードを埋めたうえで、`long-novel-orchestrator` を入口に対象話の執筆を依頼する。カードの各項目は省略せず、本文確定後は状態差分と照合する。

---

## ベストプラクティス

### 1. **書く直前**にカードを埋める（先取り設計しない）

シーンカードは直近話ほど具体化し、遠い話は状態変化と未回収事項だけに留める。重大な転換点は前後の因果を先に監査するが、先取り話数を固定しない。

### 2. previous_facts を盛りすぎない

**当該シーンの判断・物理・情報格差に直接関係する事項のみ**。項目数ではなく、本文の選択に使うかで絞る。全件の正本は `world-bible/log/canon-log.md` とし、必要部分だけ抜粋する。

### 3. NG表現タグはシーンごとに更新する

前話・同一アークで目立った語彙、比喩、文末、場面構造のうち、今回も無意識に反復しそうなものだけ書く。`guidelines/05-ai-guardrails.md` の候補一覧を毎回複製しない。

### 4. 出力後にカードと本文を照合する

章を書き終えたら、カードの **§3 シーンゴールと約束／§5 状態差分／§6 進捗／§7 話末の効果** を本文と照合する。本文が正典や主要筋を損なわず、より必然的な結果へ進んだ場合は、カードを確定本文に合わせて更新してから台帳へ反映できる。カード達成のためだけに本文を不自然に戻さない。

### 5. **書き終えたカードはアーカイブする**

`scene-cards/ep<N>.md` は書き終えても消さない。後の章で前章を参照するときの一次資料として残す。書き終えた章のカードは `frozen` 扱いで改変しない。

### 6. カードと本文が乖離した場合

執筆中にカードから外れたくなる場合、（a）**カードを直す**（プロット調整）か、（b）**本文をカードに合わせる**（設計尊重）か、を判断する。判断基準：その変更で **plot.md の伏線台帳・キャラアーク表に矛盾が出るか**。出るなら（b）、出ないなら（a）。
