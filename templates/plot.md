# プロット（中粒度設計）テンプレート

採用した構造の転換点（必要なら `templates/beat-sheet.md`）と `templates/scene-card.md`（1話単位の執筆設計）の**間に位置する**中粒度の設計図。

新作開始時に本ファイルをコピーし `work/plot.md` として保存する。執筆中は **頭から `## 章一覧（append-only）` の手前まで凍結**する。各話では現在アークと前後3話だけを読み、話を書き終えたら**章一覧の末尾だけ追記**する（途中行は改変しない）。

---

## このファイルの目的

50万字超の長編で起こる典型的な破綻――**伏線が散逸する／副筋が止まる／キャラアークが進まない／毎話「整える章」になる**――を構造的に防ぐ。全体転換点だけでは粒度が粗すぎ、シーンカードだけでは全体最適が見えない。中間に本ファイルを置くことで：

1. 章数が膨らんでも**主筋・副筋の進行が並列追跡**できる
2. 伏線の**設置→回収**が台帳で一覧でき、回収忘れ・回収過多が出ない
3. キャラごとの**内的変化（キャラアーク）**が章単位で追える
4. 「読者の感情曲線」を**章レベルで設計**できる
5. 各話のシーンカード作成時に**「いまどこ／何が確定／何が未開示」**が即座に分かる

## アーク分割（部・章クラスター）

長編は、主要な目的・対立・場所・関係の局面が変わる位置でアークに分ける。アーク数や話数は固定せず、採用した構造の転換点を配置する。

| 部 | 話範囲 | 担当する転換点 | 機能 | サブタイトル候補 |
|---|---|---|---|---|
| （例：第一部） | 第1〜N1話 | （採用構造の名称） | 主人公の従来の日常が変わるまで | （例：再構築編）|
| | | | | |

アーク境界では、前アークの結果が次の目的・関係・危険をどう変えたかを示す。リキャップや強い引きを毎回の義務にしない。

## キャラアーク表（主要キャラの内的変化）

変化する主要人物について「**起点状態 → 変化が外面化する局面 → 終点状態**」を設計する。中継点は回数で埋めず、選択と結果が不可逆に変わる箇所だけ置く。

| キャラ | 起点（第1話） | 中継1（第○話）| 中継2（第○話）| 終点（最終話）|
|---|---|---|---|---|
| 主人公 | （内的状態：例「他人を信じない」）| | | （例「条件付きで信じる」）|
| カウンターパート | | | | |
| 主要サブ1 | | | | |
| 主要サブ2 | | | | |
| 敵対者 | | | | |

**ルール**：
- 起点と終点が同じ人物も、他者や世界を測る定点、信念を守り抜く弧、変化を拒む代償として機能し得る
- 中継章は本文で「内的変化が**外面に出る瞬間**」を描く（独白だけでは弱い）

## 伏線台帳（設置→回収の対応表）

読者に問いや予測を生む意図的な伏線は設置時に記録する。単なる連続性情報や雰囲気の小物まで伏線扱いして台帳を肥大させない。回収時期が未確定なら条件またはアークを記録する。append-only。

| ID | 内容 | 設置章 | 回収章 | 種別 | 状態 |
|---|---|---|---|---|---|
| F001 | （例：「続きをやろう」というフレーズ）| 第1話 | 第136話 | 言葉 | 未回収 |
| F002 | （例：左手の傷痕）| 第2話 | 第11話／第136話 | 身体 | 未回収 |
| F003 | （例：黒衣の女が市場を横切る）| 第14話 | 第32話 | 人物 | 回収済 |
| F004 | （例：石壁の古代文字）| 第54話 | 第109話 | 物体 | 未回収 |
| F005 | （例：「権限がない」発言）| 第1話 | 第92話 | 設定 | 未回収 |

**種別**：言葉／身体／人物／物体／設定／関係。
**ルール**：
- 設置と回収の間隔は、読者が覚え、予測し、意味の変化を受け取れる長さにする。隣接話でも機能すればよい
- 本作で約束した問いは本作内で回収する。意図的な余白や続編事項は、未回収事故と区別して状態を明記する
- 回収予定章を変更したら、本表だけ書き換える（本文側に「予告」を書かない）

## 章ごとの感情曲線

各章で中心となる読者効果を決める。複数感情があっても主従を付け、同じ効果が続く場合は強度・原因・人物の反応が変わるか確認する。

| 主感情 | 短評 | 配置目安 |
|---|---|---|
| 不安 | 何が起きるか分からない／脅威の影 | きっかけ・包囲フェーズ |
| 期待 | これから何かが始まる予感 | 第一の転換・出立章 |
| 笑い | 軽妙・コミカル | 中盤の見せ場の前半 |
| 興奮 | 戦闘・スピード・大技 | 中盤の見せ場の中盤・クライマックス |
| 切なさ | 別れ・失われたもの | 最大の後退・結末 |
| 達成 | 勝利・獲得・到達 | クライマックス直前 |
| 安堵 | 帰還・癒し・日常 | 結末・後日譚 |
| 驚愕 | 真相判明・伏線回収 | 中間点・クライマックス |

例：「不安→不安→不安」と続けると読者は疲弊する。「不安→笑い→不安→驚愕」のように**緩急**を設計する。

## テンプレ展開回避（独自要素の宣言）

採用する類型、読者がその類型へ期待する報酬、本作で変える因果を宣言する。小道具や副技能を足した数ではなく、次を確認する。

- [ ] 主人公の選択と成功条件が、類型の標準展開とどこで異なるか：
- [ ] その差が人物の経歴・欲求・世界の制約から必然になっているか：
- [ ] カウンターパートと敵対者が主人公のための機能だけでなく、自分の利害で動くか：
- [ ] クライマックスの解決手段が、序盤から育てた能力・関係・代償を使うか：
- [ ] 類型の報酬を否定する場合、代わりに何を返すか：

`guidelines/05-ai-guardrails.md` の定型化候補は単語禁止ではなく、近接反復の確認に使う。

## 章一覧（append-only）

各話を書き終えたら**末尾に1行追記**する。途中行は改変しない（cache 安定化）。

| # | 通し番号 | 仮タイトル | 転換点（採用時）| 今回返した約束 | 状態変化 | 話末の効果 | 字数 | 状態 |
|---|---|---|---|---|---|---|---|---|
| 1 | 第1話 | （例：境界線）| （任意）| （序盤の約束）| 立場が変わる | 異常事態 | | 確定 |
| 2 | 第2話 | （例：再構築）| | | 関係が変わる | 小さな安堵 | | 確定 |
| 3 | 第3話 | | | | | | | 計画 |
| ... | | | | | | | | |

**転換点**：構造テンプレートを採用した場合だけ名称または番号を書く。
**今回返した約束**：`§読者への約束・投稿戦略ブリーフ` に対して、本文で実際に返したものを書く。
**状態変化**：情報、関係、位置・期限・危険、決断、喪失・獲得など、以後の選択を変える差分を書く。
**話末の効果**：問い、異常事態、選択、達成、安堵、余韻、意味の反転などを具体的に書く。
**状態**：計画／執筆中／確定。

## Grokでの参照範囲

通常話では、作品基本情報、現在アーク、伏線台帳、キャラアーク、章一覧の前後3話を読む。アーク境界、設定変更、重大な矛盾の疑いがある場合のみ全文を監査する。

`§章一覧` は append-only とし、現在状態の正本は `work/continuity/current-state.md`、確定事項の正本は `world-bible/log/canon-log.md` に分離する。

## ベストプラクティス

### 1. プロットを書き終わってから本文を書く（プロット先行）

第1話を書き始める前に、全体の主要転換点、現在アーク、結末で返す約束を置く。遠い章を偽精度で埋めず、近い章ほど具体化する。転換点シートを採用した場合だけ、その対応を確認する。

### 2. 副筋の次回条件を持つ

副筋ごとに「次に動く条件」「止まっている理由」「停止中も変化する圧力」を記録する。話数ノルマで割り込ませず、長く触れない場合に忘却か意図的保留かを監査する。

### 3. キャラアークの中継点を本文で「外面化」する

「内心が変わった」だけでは読者に伝わらない。中継章では**台詞・行動・選択**でキャラの内的変化を外面化する。例：「他人を信じない」主人公が中継章で**初めて他人に背中を預ける場面**を描く。

### 4. 伏線回収章の本文を書く前に、伏線台帳を確認する

`plot.md` の `## 伏線台帳` を必ず参照し、当該章で**回収予定**になっている伏線IDをシーンカードに転記する。回収忘れの最頻パターン。

### 5. 章一覧は追記を基本にする

書き終わった章の行は原則として改変しない。確定内容を直す必要がある場合は、章本文、scene-card、状態台帳、正典を同じ作業で照合して直接修正し、別の改訂履歴は残さない。

### 6. 話数を見栄えで調整しない

丸い数字も端数も品質の証拠ではない。約束と主要因果が閉じる位置で完結し、話数を見栄えやAI判定対策のために増減しない（`guidelines/04-structure-and-plot.md §2-2`）。
